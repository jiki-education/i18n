## 소개

이 단계에서는 OpenCode나 이와 비슷한 도구를 이미 설치하셨다고 가정할게요. 아직 설치하지 않았다면 [에이전틱 코딩 플랫폼 설치 가이드](/guides/installing-an-agentic-coding-platform)를 먼저 따라해 주세요.

클러치가 무슨 일을 하는지 몰라도 자동차를 운전할 수 있는 것처럼, 에이전틱 코딩 도구도 원리를 몰라도 사용할 수 있어요. 하지만 조금만 이해해도 큰 차이를 만들어요. 도구가 어떤 때는 천재 같고 어떤 때는 당황스러운 이유, 왜 비용이 드는 경우가 있는지, 그리고 어떻게 하면 훨씬 더 나은 결과를 얻을 수 있는지를 설명해 줘요. 알아두면 좋은 개념들이에요.

## 모델

**모델**(또는 LLM, '대규모 언어 모델'의 약자)이 실제 AI예요. OpenCode나 Claude Code 같은 도구는 스스로 똑똑한 게 아니에요. 이 도구들은 연결 고리 역할을 해요: 여러분의 요청과 코드를 모아서 모델에게 보내고, 돌아오는 응답에 따라 행동해요. 모델이 바로 '두뇌'예요.

여러 회사에서 만든 수많은 모델이 있고, 여러분에게 중요한 세 가지 측면에서 차이가 나요:

- **성능.** 더 크고 최신 모델은 복잡한 문제를 이해하고 올바른 코드를 작성하는 데 더 뛰어나요. 가장 뛰어난 모델('프런티어' 모델이라고도 불러요)은 나머지보다 눈에 띄게 똑똑해요.
- **속도.** 작은 모델은 더 빠르게 응답해요. 간단한 질문에는 빠른 모델이 더 쾌적한 경험을 주는 경우가 많아요.
- **비용.** 최상위 모델은 충분히 쓸 만한 모델보다 50배 더 많은 비용이 들 수 있어요. 그래서 무료 요금제에서는 작은 모델이나 프로모션 모델을 사용하는 거예요.

영원한 '최고의 모델'은 없어요. 리더보드는 몇 달마다 뒤바뀌기 때문에, 모델을 자유롭게 전환할 수 있는 도구를 추천하는 이유 중 하나예요 (OpenCode에서는 `/models`를 입력하세요).

## 토큰

모델은 글자나 단어 단위로 읽지 않아요. **토큰**이라는 작은 텍스트 조각으로 읽어요. 평균적으로 한 단어의 약 4분의 3 정도 크기예요. 'Understanding'은 하나의 토큰이고, 'Misunderstanding'은 세 개의 토큰일 수 있어요.

모델에 보내는 모든 내용은 토큰으로 잘게 쪼개지고, 모델이 작성하는 모든 내용도 토큰 단위로 돌아와요. 그래서 응답이 한 번에 나타나는 대신 단어들이 흘러나오듯 보이는 거예요.

토큰이 중요한 가장 큰 이유는 바로 **비용이 토큰 단위로 청구되기 때문이에요.** 모델 가격은 모델이 읽는 부분('입력')과 쓰는 부분('출력') 모두 100만 토큰당 가격으로 표시돼요. 에이전트가 코드 파일 5개를 읽으면 수만 개의 입력 토큰이 발생할 수 있어요. 그래서 무료 요금제에는 한계가 있고, 큰 프로젝트에서 작업하는 에이전트가 간단한 질문에 답하는 것보다 비용이 더 드는 거예요.

## 컨텍스트 윈도우

모델은 기억력이 없어요. 메시지를 보낼 때마다, 도구는 지금까지의 전체 대화 내용과 에이전트가 읽은 모든 파일을 다시 한꺼번에 보내요. 모델의 **컨텍스트 윈도우**는 한 번에 보낼 수 있는 최대 크기로, 토큰 수로 측정되는 작업 기억 용량이에요.

여기에서 두 가지 실용적인 점을 알 수 있어요:

- **긴 세션은 품질이 떨어져요.** 대화가 길어지면 컨텍스트는 옛날 우회 경로와 오래된 파일 내용으로 가득 차게 돼요. 컨텍스트가 꽉 차면 모델의 집중력이 눈에 띄게 떨어지는 게 측정할 수 있어요. 긴 세션 후반부에 에이전트가 어이없는 실수를 하기 시작하면, 보통은 멍청해져서가 아니라 너무 많은 정보에 묻혀서 그래요.
- **새로 시작하는 건 공짜예요.** 깔끔하고 명확한 요청으로 새 세션을 시작하는 것이, 지저분해진 세션을 붙잡고 계속하는 것보다 나은 경우가 많아요. 대화 기록에 미련을 두지 마세요.

## 프롬프트

**프롬프트**는 여러분이 모델에게 쓰는 말 그 자체예요. 에이전틱 코딩에서 가장 큰 효과를 내는 기술은 좋은 프롬프트를 작성하는 거예요. `fix my code`라고 쓰는 것과 `the tests in this folder fail with this error message, and I expected the function to return 5, not 3`라고 쓰는 것의 차이는, 에이전트가 추측하느냐 알고 있느냐의 차이예요.

좋은 프롬프트는 세 가지를 말해줘요: 무엇을 달성하려는지, 실제로 무슨 일이 벌어지고 있는지, 이미 무엇을 시도해봤는지. 도움을 요청하는 동료에게서 듣고 싶은 내용이 바로 그거예요.

## 에이전틱 루프

에이전트와 챗봇을 구분하는 것은 **루프**예요. 에이전트에게 작업을 주면 단순히 답변만 하지 않아요. 에이전트는 이렇게 일해요:

1. 무엇을 알아야 할지 결정하고, **도구**(파일 읽기, 검색, 명령 실행)를 사용해서 찾아내요.
2. 변경을 적용해요.
3. 보통 코드나 테스트를 실행해서 자기 작업을 확인해요.
4. 실패하면 새로운 정보를 가지고 1단계로 돌아가요.

이 루프를 지켜보는 것은 정말 배울 점이 많아요: 경험 많은 프로그래머가 실제로 작업하는 방식을 꽤 잘 보여주거든요. 조사하고, 한 가지를 바꾸고, 확인하고, 반복해요. 루프가 돌아가는 동안 여러분의 역할은 감독이에요.

도구는 중요한 작업을 하기 전에 허락을 구할 거예요. 무조건 승인하지 말고, 제안 내용을 꼭 읽어보세요.

## 환각, 또는 모델이 확신에 차서 틀릴 때

모델은 여러분처럼 아는 것이 아니에요. 가장 그럴듯해 보이는 응답을 만들어내는데, 가끔은 그 가장 그럴듯한 응답이 단순히 틀린 경우도 있어요: 존재하지 않는 함수, 실제로는 없는 설정, 빈틈없이 들리지만 사실은 잘못된 설명 같은 거예요. 이를 **환각**이라고 해요. 최고의 모델에서도 완전히 사라지지는 않아요.

이에 대한 방어책은 전문가들이 쓰는 것과 똑같아요: **절대 믿지 말고, 항상 확인하세요.** 코드를 실행해 보세요. 변경 사항을 수락하기 전에 읽어보세요. 설명이 중요하다면 모델에게 그 설명의 근거가 된 코드 줄을 보여 달라고 하세요. 에이전트는 루프 안에서 실제로 실행하고 결과를 보기 때문에 챗봇보다 이런 문제가 훨씬 적지만, 확인하는 습관은 처음부터 길러야 해요.

## 개인 정보 보호

한 가지 더 알아둘 점이 있어요. 특히 무료 요금제에서는: 무료 모델은 보통 그 모델을 개선하기 위해 대화 내용을 수집하는 회사 덕분에 무료인 경우가 많아요. 학습 목적으로는 괜찮은 거래예요. 하지만 무료 모델에 보내는 모든 내용은 공개될 수 있다고 생각하세요: 비밀번호나 개인 정보는 보내지 말고, 나중에 커리어가 쌓이면 회사 규정을 확인하기 전에는 사내 코드를 보내지도 마세요.

## 기초는 이게 전부예요

모델은 '두뇌', 토큰은 화폐, 컨텍스트는 기억, 프롬프트는 운전대, 그리고 루프가 에이전트를 만드는 요소예요. 나머지는 직접 부딪혀 보면서 익히게 될 거예요. 바로 그렇게 해보시길 권해요. 아직 도구를 설치하지 않았다면, 저희 [설치 가이드](/guides/installing-an-agentic-coding-platform)를 따라 하면 10분 안에 준비가 끝나요. 그런 다음 Learn to Build의 첫 번째 [프론트엔드 기초](/build/frontend-basics/setting-up-the-project) 세션을 보면서 실제로 작동하는 모습을 확인하세요.
