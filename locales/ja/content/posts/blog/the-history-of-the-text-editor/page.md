## はじめに

私がプログラミングを始めてから30年、ほぼ毎日テキストエディタを使ってきました。さまざまなエディタを試し、どれが一番かについて時々やや宗教的なこだわりを持つようになりました。

その間ずっと、新しいエンジニアにとって最初の通過儀礼の一つは、テキストエディタをインストールして使い方を覚えることでした。しかし、エージェントによるコーディングがエンジニアの意味するものを変えつつある中で、テキストエディタが支配的な時代は終わりを迎えようとしているのかもしれません。

そこで、テキストエディタの歴史を振り返ってみましょう。カードに穴を開ける時代から、1行ずつ印刷しながら編集するラインエディタ、さらにはViとEmacsの、現在生きている人の大半よりも古いライバル関係まで。これが地味なテキストエディタの物語です。

## エディタ以前: カードに穴を開ける時代（1950年代〜1960年代）

画面にコードを表示せずにプログラミングをするなんて想像しにくいですが、そこが出発点でした。

1950年代から1960年代には、画面はまだ発明されておらず、代わりにプログラムは、1行のコードにつき1枚のカードに物理的に穴を開けて（あるいは紙テープに）保存されていました。「編集」とは、カードを打ち直すか、物理的にカードをデッキから抜き差しすることでした。

今では自分のコードが実行に数秒以上かかると、フィードバックの遅さにひどくイライラしてしまいますが、当時はフィードバックに何時間もかかりました。カードのデッキをオペレーターに渡すと、オペレーターはそれを実行待ちのジョブのキューに入れます。結果の印刷物が戻ってくるのは数時間後、あるいは数日後でした。「タイプミス」なんてものはなかったんでしょうね…！

## コンピューターが応答し始める（1960年代）

二つの発明が、編集をその遅いバッチ処理の世界から対話的なものへと引きずり出しました。

一つ目は**テレタイプ**です。テレタイプは、あらかじめ穴を開けたカードの束という概念を置き換えました。代わりに、キーボードで入力を行います。打鍵はリアルタイムでマシンに送られ、マシンは応答を紙のロールに直接印刷しました。まだ画面はありませんでしたが、初めて、段ボールの山ではなく、コンピューターとのリアルタイムのやりとりが可能になったのです。

二つ目は**タイムシェアリング**です。タイムシェアリングがなければ、コンピューターは一度に一人のユーザーにしか接続できず、その人のタイピング速度や応答処理に律速され、大量の待ち時間が発生していました。タイムシェアリングは、マシンが複数のユーザーの間を高速で切り替えることでこの問題を解決しました。複数の人が一台のマシンに接続でき、切り替えが非常に速いため、各自がマシンをまるごと占有しているかのような錯覚を得られたのです。

この二つが組み合わさることで、マシンとの本格的な会話が可能になりました。そして、会話ができれば、座ったままコードを一行ずつ編集できるようになります。カードを打ち直して祈る必要はありません。まさに、最初の本格的なエディタがそれを可能にしました。

## ラインエディタの登場: ed、QED、TECO（1962年〜1971年）

1960年代には、もう一つの大きなパラダイムシフトが起こりました。プログラムは、持ち運ぶ物理的なオブジェクト（箱に入ったカードデッキ）ではなく、コンピューター自身のディスク上に存在する名前付きのファイルになったのです。プログラムを変更するために新しいカードを印刷する代わりに、実際にプログラムを編集できるようになりました。

ただし、まだ画面はありませんでした。その代わり、実行したことのすべてと、その結果が紙に印刷されました。その印刷物が「ハードコピー」と呼ばれるもので、コンピューターに与えた指示の永続的な記録です。

これが、現代のエディタに似たものが初めて登場した瞬間ですが、それらは**行指向**であり、まだかなり異質なものでした。一度に一行ずつ作業し、コマンドベースで操作しました。コマンド（Vimを使ったことのある人なら非常に馴染み深いものもあります）を発行すると、そのコマンドが変更を加えます。例えば、詩のタイプミスを修正するには次のようにしました。

```
input         output            what it does
------------  ----------------  ----------------------------------------
ed poem       45                open the file "poem"; ed prints its size
1,$p                            print all lines - ed then replies:
              Roses are red
              Violets are blu   the typo!
              Sugar is sweet
2             Violets are blu   jump to line 2; ed prints it
s/blu/blue/                     on this line, change blu to blue
p             Violets are blue  print the current line (now fixed)
w             46                write/save; ed prints the new size
q                               quit
```

この時代にプログラミングをしていた少数の人々は、おそらくこの時期の注目すべきエディタとして次の三つを挙げるでしょう。

- **TECO**は1962年にMITのダン・マーフィーによって作成され、元々は穴の開いた紙テープを編集するためのものでした。難解なことで有名で、プログラミング言語としても機能しました（これは後で重要になります）。
- **QED**は1965/66年にバークレーのバトラー・ランプソンとL・ピーター・ドイチュによって作成され、最初のラインエディタの一つです。その2年後、ケン・トンプソンがこれを書き直し、**正規表現**（テキスト内のパターンを照合するために使用されるプログラミング言語の一種）を初めてエディタに導入しました。
- **ed**は1970年代初頭にベル研究所のケン・トンプソンによってリリースされ、QEDのアイデアを最小限にまで削ぎ落としたエディタで、最初のUnixに同梱されました。`ed`は現在でもすべてのMacとLinuxマシンにインストールされており、そのコマンド言語は`grep`、`sed`、そしてViの`:`コマンドの直接の祖先です（いずれも[Exercismのトラック](http://exercism.org/tracks)があり、学ぶことができます！）。

TECOには、広く最古のソフトウェアイースターエッグ（現在多くのゲームに見られる隠し機能）と考えられているものも存在します。後のバージョンのTECOで`make love`と入力すると、`not war?`というおどけた返答が返ってきました。これは1967年頃にスタンフォードAIラボで密かに組み込まれたもので、ビデオゲームでイースターエッグが一般的になる約10年前のことです。[TECOをインストール](https://github.com/blakemcbride/TECOC)して試してみてください！

## ページ全体を見る: BravoとWYSIWYG（1974年）

一方、**Xerox PARC**では、物語の別の流れが始まっていました。

1974年、バトラー・ランプソンとチャールズ・シモニーが**Bravo**をリリースします。これは初の**WYSIWYG**エディタであり、ビットマップ画面に本物のフォントで整形されたテキストを表示し、**マウス**を使ってテキストを選択できました（マウスの特許自体はもっと古いのですが、それはまた別の機会に！）。

Vimに少し似て、二つのモードを持っていました。キーを押すと「何かを行う」「コマンドモード」と、キーを押すと画面に文字が入力される「挿入モード」です。

これは実は、この物語における重要な分岐点です。一方で、シモニーは後にこれらのアイデアをマイクロソフトに持ち込み、Wordを開発し、ワードプロセッサを世に送り出しました。もう一方で、画面、マウス、モーダル編集は、その後のコードエディタに直接受け継がれていきました。

## 偉大なるライバル関係: ViとEmacs（1976年以降）

<figure class="post-figure">
  <img src="/images/blog/the-history-of-the-text-editor/emacs.webp" alt="GNU Emacsでコードを編集しているスクリーンショット" />
  <figcaption>GNU Emacs。スクリーンショット提供: tecosaur、<a href="https://commons.wikimedia.org/wiki/File:Writing_and_compiling_C%2B%2B_in_Emacs.png">Wikimedia Commons</a>経由、CC BY-SA 4.0。</figcaption>
</figure>

- 物語の核心：**1976年**、アメリカの対岸同士で、今日でも本格的なプログラミングを支配する二つのエディタが、正反対の哲学から生まれました。
- **Emacs**（MIT: リチャード・ストールマン、デビッド・ムーン、ガイ・スティール共著）：**TECO用のマクロ集**（"Editor MACroS"）としてスタートしました。
- Emacsの大きなアイデア：エディタはユーザーによって**無限にプログラマブルで拡張可能**であるべきだ。それはテキストエディタというより、たまたまテキストを編集するLisp環境と言えます。
- ストールマンは1984年に**GNU Emacs**として再構築し、それはフリーソフトウェア運動の旗艦となりました。
- **Vi**（バークレー: 当時大学院生で、後にSunを共同設立するビル・ジョイ）：edの行編集コアの上に構築された、フルスクリーンの**ビジュアル**モードです。

<figure class="post-figure">
  <img src="/images/blog/the-history-of-the-text-editor/vim.webp" alt="Vimでコードを編集しているスクリーンショット" />
  <figcaption>Viの最も人気のある現代の子孫であるVim。スクリーンショット提供: Carolinedmoreschi、<a href="https://commons.wikimedia.org/wiki/File:Dracula_Theme_being_used_on_Vim.png">Wikimedia Commons</a>経由、CC BY-SA 4.0。</figcaption>
</figure>

- Viは過酷な制約の下で設計されました：**300ボーのモデム**越しでも使える必要があり、画面に送られる一文字一文字が貴重でした。
- その希少性がViの真骨頂である**モーダル編集**を生み出しました。キーストロークがテキストを移動・変換するためのコンパクトなコマンド言語になるのです。
- **Vim**（"Vi IMproved"、1991年）は、複数レベルの元に戻す、シンタックスハイライト、プラグインを追加しました。**Neovim**が後にこれをさらに近代化しました。
- 両陣営の**「エディタ戦争」**はソフトウェア最古のライバル関係であり、それは実際には哲学的な分裂です：Emacs（最大限、プログラマブル、何でもできる環境）対 Vi（最小限、モーダル、容赦なく効率的）。
- 両方とも50年近く経った今でも日常的に使われており、これはどんなソフトウェアにとっても驚くべきことです。

## それ以外の私たちのためのエディタ: BBEdit、TextMate、Sublime（1992年〜2008年）

- グラフィカルなオペレーティングシステムが成熟するにつれて、ターミナルではなくネイティブのGUIを求めるエンジニア向けに、新しいクラスのエディタが登場しました。
- **BBEdit**（1992年、Mac）：長く愛される「ダメじゃない」エディタ。
- **TextMate**（2004年、Mac）：**Ruby on Rails**ブームの際に非常に大きな影響を与えました。その「バンドル」とスニペットシステム、そしてシンタックスハイライト用の文法フォーマットは、今日でもVS Codeが使用するデファクトスタンダードとなりました。
- **Sublime Text**（2008年）：高速、クロスプラットフォーム、ミニマル。ミニマップ、マルチカーソル、ファジーコマンドパレットなど、誰もが真似したものを導入しました。
- Sublimeは、「ターミナルエディタ」と「重量級IDE」の間に巨大な市場があることを証明しました。

## Web技術の時代: AtomとVS Code（2014年〜2015年）

<figure class="post-figure">
  <img src="/images/blog/the-history-of-the-text-editor/vscode.webp" alt="VSCodium（VS Codeのオープンソースビルド）のスクリーンショット" />
  <figcaption>VSCodium（VS Codeの完全オープンソースビルド。Microsoftのリリースと見た目は同一ですが、MITライセンスのためここに掲載できます）。スクリーンショット提供: <a href="https://commons.wikimedia.org/wiki/File:VSCodium_official_screenshot.png">Wikimedia Commons</a>経由、MIT。</figcaption>
</figure>

- **Atom**（GitHub、2014年）：「21世紀のためのハック可能なテキストエディタ」。後に**Electron**となる技術を用いてWeb技術（HTML、JS、Node）で構築されました。Emacsのようにハック可能ですが、動作は遅かったです。GitHubは2022年12月に開発を終了しました。
- **VS Code**（Microsoft、2015年）：同じくElectronベースですが、より高速で、すぐに使える機能（オートコンプリート、デバッグ、Git内蔵）が満載でした。決定的な勝利を収め、現在は支配的な地位を占めています。
- VS Codeの最も重要な構造的アイデアは、**Language Server Protocol（LSP）** でした。
- LSP以前は、各エディタが各言語の「理解」（オートコンプリート、定義への移動、エラーチェック）をゼロから再実装する必要がありました。
- LSPにより、言語は一つの「サーバー」を提供し、どのエディタもそれと通信できるようになりました。これにより、言語のインテリジェンスがエディタから切り離され、現在では業界標準となっています。

## AI時代: あなたと一緒に書くエディタ（2021年以降）

- 最新の章では、エディタはテキストを操作するツールから、**共同作業者**へと変わります。
- **GitHub Copilot**（2021年）：インラインAIオートコンプリート。後に独自の言語サーバーを通じて公開され、どのエディタでもプラグインできるようになりました。
- **Cursor**と**Windsurf**：VS Codeのフォークであり、VS Codeの拡張機能を維持しつつ、編集ループをAI中心（マルチファイル編集、チャット、エージェント）に再構築しています。
- **Zed**（Rust、2024年にオープンソース化）：速度、コラボレーション、AIのためにゼロから構築された、GPUアクセラレーションによるエディタです。
- **エージェントツール**（Claude Codeなど）：「エディタ」がますます自ら動かし、人間はタイプするのではなくレビューし指示する役割へと変わります。
- 興味深いことに、LSPは再び再利用され、今度はAIエージェントにテキスト検索による推測ではなく、正確なコードインテリジェンスを提供しています。

## 一つの時代の終わり？（現在）

- この物語のどの時代も、アイデアを思いついてからそれを動かすまでのギャップを縮めてきました：バッチカード（数時間）、ラインエディタ（一行ずつ）、フルスクリーンエディタ（ファイル全体）、IDEのインテリジェンス（エディタがコードを理解する）、そしてAI（エディタがあなたと一緒に書く）。
- それでもなお、1976年生まれの二つのエディタ、ViとEmacsは、依然としてここにあります。根本的なアイデア（モーダルな効率性、プログラマブルな拡張性）は、あらゆるハードウェアの波よりも長く生き残りました。
- 50年間、自分のエディタを学ぶことは通過儀礼でした。それが変わりつつあるのかもしれません。
