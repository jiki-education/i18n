## Einleitung

Wenn du anfängst, auf deinem eigenen Computer Code zu schreiben, brauchst du einen Ort dafür. Dieser Ort ist ein Code-Editor. Er ist eines der ersten Tools, zu denen du greifen wirst, und der Ort, an dem du im Laufe deiner Karriere viel Zeit verbringen wirst. Wahrscheinlich wirst du im Laufe der Zeit immer wieder wechseln und neue ausprobieren. Deshalb lohnt es sich zu verstehen, was ein Code-Editor ist und wie du einen guten für den Anfang auswählst.

## Ein Code-Editor ist kein Textverarbeitungsprogramm

Man könnte leicht annehmen, dass jedes Programm, in dem du tippen kannst, ausreicht. Der häufigste Fehler ist, zu einem Textverarbeitungsprogramm wie Microsoft Word oder Google Docs zu greifen. Diese Programme sind dafür gemacht, Dokumente zu schreiben, die Menschen lesen, also ändern sie im Hintergrund, was du eingibst. Sie machen aus geraden Anführungszeichen geschwungene „intelligente“ Anführungszeichen, korrigieren deine Wörter automatisch und speichern versteckte Formatierungen. All das macht Code kaputt.

Ein Code-Editor ist eine Art Texteditor. Er arbeitet mit reinem Text und fügt nie versteckte Formatierungen hinzu, sodass der Computer genau das sieht, was du tippst. Der Unterschied ist, dass ein Code-Editor ein Texteditor ist, der speziell für Code gebaut wurde. Über reinen Text hinaus versteht er die Struktur dessen, was du schreibst, und hilft dir auf Weisen, wie es ein Textverarbeitungsprogramm nie könnte:

- **Syntax-Highlighting** färbt die verschiedenen Teile deines Codes ein, damit du ihn leichter lesen und Fehler schneller erkennen kannst.
- **Automatische Einrückung** hält deinen Code ordentlich ausgerichtet, was in vielen Sprachen sehr wichtig ist.
- **Fehlerhinweise** zeigen Probleme auf, oft schon bevor du das Programm überhaupt ausführst.
- **Autovervollständigung** schlägt den Rest dessen vor, was du gerade tippst, sodass du schneller schreibst und weniger Tippfehler machst.
- **Erweiterungen** lassen dich Unterstützung für neue Sprachen und Tools hinzufügen, je weiter du kommst.

## Der Editor, den wir empfehlen

Es gibt viele gute Code-Editoren, und du kannst hier nichts falsch machen. Trotzdem empfehlen wir **Visual Studio Code**, meist kurz VS Code genannt. Er ist kostenlos, läuft auf Windows, macOS und Linux, ist anfängerfreundlich und einer der meistgenutzten Editoren der Welt. Fast jedes Tutorial, das du findest, geht also davon aus, dass du ihn verwendest.

Wenn du bereit bist, ihn zu installieren, folge unserer Anleitung zum [Installieren von VS Code](/guides/installing-vscode).

## Andere Editoren, von denen du vielleicht hörst

Du brauchst keinen davon, um mit Jiki mitzukommen, aber du wirst ihnen begegnen. Deshalb hier ein kurzer Überblick über die gängigen:

- <a href="https://code.visualstudio.com" target="_blank" rel="noopener noreferrer">Visual Studio Code (VS Code)</a> ist der kostenlose, plattformübergreifende Editor, den wir empfehlen.
- <a href="https://www.sublimetext.com" target="_blank" rel="noopener noreferrer">Sublime Text</a> ist ein schneller, schlanker Editor, der seit vielen Jahren beliebt ist.
- <a href="https://zed.dev" target="_blank" rel="noopener noreferrer">Zed</a> ist ein neuerer, sehr schneller Editor, der auf Geschwindigkeit und Zusammenarbeit ausgerichtet ist.
- <a href="https://www.jetbrains.com/ides/" target="_blank" rel="noopener noreferrer">JetBrains IDEs</a> (integrierte Entwicklungsumgebungen wie <a href="https://www.jetbrains.com/pycharm/" target="_blank" rel="noopener noreferrer">PyCharm</a> und <a href="https://www.jetbrains.com/idea/" target="_blank" rel="noopener noreferrer">IntelliJ IDEA</a>) sind mächtige, schwerere Tools für professionelle Entwickler, die an großen Projekten arbeiten.
- <a href="https://www.vim.org" target="_blank" rel="noopener noreferrer">Vim</a> und <a href="https://neovim.io" target="_blank" rel="noopener noreferrer">Neovim</a> sind tastaturgesteuerte Editoren, die im Terminal leben. Erfahrene Entwickler lieben sie sehr, aber die Lernkurve ist steil.

Unser Rat, während du lernst, ist einfach: Fang mit VS Code an, werde sicher im Schreiben von Code und probier die anderen später aus, wenn du weißt, was dir gefällt.
