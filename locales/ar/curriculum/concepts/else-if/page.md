لقد رأيت كيف يمنحك `if` و`else` مسارين: أن تفعل شيئاً عندما يكون الشرط صحيحاً، وشيئاً آخر عندما يكون خاطئاً. لكن ماذا لو كان لديك أكثر من إمكانيتين؟

تخيل أن حارس النادي الخاص بنا يبيع التذاكر. تحت سن الثالثة عشرة، تحصل على تذكرة طفل. بين الثالثة عشرة والعشرين، تحصل على تذكرة مراهق. في سن العشرين أو أكثر، تكون التذكرة للبالغين. إذن لديك الآن ثلاث نتائج مختلفة. لهذا، يمكننا إضافة جملة `if` أخرى بعد `else`. فيمكننا القول: "إذا كان هذا، فافعل هذا. وإلا إذا كان هذا، فافعل ذاك. وإلا، فافعل هذا الشيء الآخر." إذن في هذا المثال، سيرى Jiki جملة `if` ويتحقق من الشرط الأول. هل ستة عشر أقل من ثلاثة عشر؟ لا. فينتقل إلى `else if`. هل ستة عشر أقل من عشرين؟ نعم، هذا صحيح. فيقوم بتنفيذ تلك الكتلة ويعطي تذكرة مراهق. لكنه بعد ذلك ينتهي. لا يتحقق من أي شيء آخر. لا ينظر إلى ذلك `else` الأخير على الإطلاق. بمجرد أن يجد Jiki شرطاً صحيحاً، ينفّذ تلك الكتلة، ويتخطى كل ما تحتها.

```javascript
if (age < 13) {
  childTicket()
} else if (age < 20) {
  teenTicket()
} else {
  adultTicket()
}
```

هذا هو الشيء الأساسي الذي يجب فهمه. لا تُنفَّذ سوى كتلة واحدة فقط. يمضي Jiki في هذه السلسلة من العبارات، يجد أول شرط صحيح، ينفّذ تلك الكتلة، ثم ينتقل إلى ما بعدها.

الآن، هناك شيء واحد يجب أن تفهمه جيداً لأنه يُربك الكثيرين. هناك فرق دقيق لكنه مهم جداً بين كتابة جملتي `if` منفصلتين واستخدام `else if`. تخيل أننا ننشئ برنامجاً يمنح إما جائزة أساسية أو جائزة إضافية بناءً على نتيجة شخص ما. انظر إلى هذين الاحتمالين. الأول يستخدم `else if` والآخر يستخدم جملتي `if` منفصلتين. ماذا سيحدث بشكل مختلف؟

```javascript
if (score > 100) {
  bonusPrize()
} else if (score > 50) {
  basicPrize()
}
```

```javascript
if (score > 100) {
  bonusPrize()
}
if (score > 50) {
  basicPrize()
}
```

إذن في الحالة الأولى، مع `else if`، نتحقق من النتيجة العالية ونمنح الجائزة الإضافية، ثم لا ننفّذ `else if`. لذا فالشخص، إذا كانت نتيجته فوق المئة، يحصل على الجائزة الإضافية فقط.

لكن في المثال الثاني، جملتا `if` مستقلتان تماماً. كلتاهما ستنفذان وكلتاهما سيكون شرطها صحيحاً. لذا فالشخص هنا يحصل على جائزتين. في الحالة الأولى، جائزة واحدة. في الحالة الثانية، جائزتان. خذ لحظة لتتأكد أنك فهمت ذلك جيداً.

من المثير للاهتمام أيضاً أن كلا الطريقتين قد تكون صحيحة اعتماداً على كيفية تصميم اللعبة. ربما يحصل المتسابق على جائزة عادية وجائزة إضافية، أو ربما يتم ترقيته فقط إلى الجائزة الإضافية. لا توجد قطعة كود صحيحة أو خاطئة. إنها فقط مفيدة في مواقف مختلفة. لكن عليك أن تعرف أيّاً منهما تنوي استخدامه.
