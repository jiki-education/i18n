## Εισαγωγή

Το να μπορείς να δημιουργείς είναι μία από τις μεγάλες χαρές της ζωής. Δεν ήμουν ποτέ καλός στο σχέδιο ή στη ζωγραφική, αλλά εδώ και 30 χρόνια, ο code είναι το εργαλείο που επέλεξα για να δημιουργώ. Μου επέτρεψε να φτιάξω προϊόντα που βοηθούν εκατομμύρια ανθρώπους, υπήρξε διέξοδος για τη δημιουργικότητά μου και ένα μέρος για να προκαλώ διανοητικά τον εαυτό μου.

Και κατά τη διάρκεια αυτών των 30 ετών, η διαδρομή για την είσοδο στην τεχνολογία ήταν σταθερή:

1. Μάθε τα βασικά του προγραμματισμού.
2. Άρχισε να φτιάχνεις απλά πράγματα.
3. Βελτίωσε τις δεξιότητές σου στον προγραμματισμό.
4. Φτιάξε πιο σύνθετα πράγματα.
5. Πήγαινε στο βήμα 3 (επανάλαβε για πάντα!)

Κάποια στιγμή, θα ήσουν έτοιμος να κάνεις αίτηση για μια δουλειά. Και θα σε εξέταζαν στο πόσο καλά γνώριζες μια γλώσσα προγραμματισμού ή έναν αλγόριθμο ή στο αν μπορούσες να χειριστείς δομές δεδομένων.

**Ο code ήταν πάντα ο φύλακας της πύλης.** Αυτό που έπρεπε να κατακτήσεις για να μπορέσεις να κάνεις οτιδήποτε. Κυριολεκτικά δεν μπορούσες να χρησιμοποιήσεις μια τεχνολογία αν δεν ήξερες να γράφεις code για να τη λειτουργήσεις. Δεν μπορούσες να βρεις δουλειά αν δεν είχες στέρεες δεξιότητες προγραμματισμού.

Όμως τώρα, χάρη στα Μεγάλα Γλωσσικά Μοντέλα (LLMs), όλα αυτά αλλάζουν.

Σε 5 χρόνια, κανείς δεν θα σε προσλαμβάνει για τις δεξιότητές σου στον προγραμματισμό. Είναι άσχετες. Δεν έχω γράψει σχεδόν ούτε μία γραμμή code τον τελευταίο χρόνο, αλλά μέσω του Claude, έχω παραγάγει εκατοντάδες χιλιάδες γραμμές code. Και λειτουργούν. Συνυπάρχουν με συνεκτικό τρόπο και τροφοδοτούν πλατφόρμες όπως το [Jiki](https://jiki.io) και έχουν επιλύσει αμέτρητα bugs στα [Exercism](https://exercism.org), [Kaido](https://kaido.org) και [Giki](https://gikiactions.com). Αλλά το κάνουν μόνο επειδή ξέρω τι κάνω. Χωρίς την καθοδήγηση ενός ανθρώπου, δεν θα είχαν φτάσει εδώ.

Η αξία ενός προγραμματιστή δεν βρίσκεται στην ικανότητά του να γράφει code ([αν και πρέπει ακόμα να ξέρεις πώς!](/blog/should-i-still-learn-to-code-in-2026)). Βρίσκεται στην **ικανότητά του να φτιάχνει πράγματα σωστά**.

Και αυτό ήταν πάντα αλήθεια. Οι προγραμματιστές λογισμικού πάντα προσλαμβάνονταν για την ικανότητά τους να κατασκευάζουν λογισμικό, να αναπτύσσουν συστήματα, να επιλύουν bugs. **Δεν προσλαμβάνονταν επειδή μπορούν να πληκτρολογούν code καλά.** Υπάρχει δεξιότητα στη συγγραφή code, αλλά μόνο ως μηχανισμός για να εκφράζεις βαθύτερο εννοιολογικό σχεδιασμό.

Δεν χρειάζεται πια να υφαίνεις χειρωνακτικά. Έχεις έναν υπερ-ευφυή αργαλειό που κάνει αυτή τη δουλειά για σένα. Η δουλειά σου είναι να ξέρεις πώς να τον καθοδηγείς, να τον ελέγχεις και να τον συντηρείς σοφά.

### Τι πρέπει να κάνω;

Ο νέος σου βρόχος είναι:

1. Φτιάξε κάτι.
2. Κατανόησε πώς λειτουργεί (και ο code και οι ιδέες).
3. Επανάλαβε το βήμα 1.

Για να το κάνεις αυτό χρειάζεσαι δύο πράγματα:

- Έναν οδηγό (👋)
- Διάθεση να πειραματιστείς, να παίξεις και να μάθεις!

Και πρέπει να το κάνεις αυτό το παιχνίδι και τη μάθηση στα όρια των γνώσεών σου. Πρέπει να συνεχίσεις να δοκιμάζεις νέα πράγματα και να **επενδύεις στην κατανόηση του τι συμβαίνει**.

### Η παγίδα

Είναι τετριμμένο με τον Claude να πεις «Φτιάξε μου μια αρχική σελίδα» και μετά επαναληπτικά να πεις «Κάνε αυτό το πράσινο κουτί μπλε» ή «Κάνε το μέγεθος της γραμματοσειράς λίγο μεγαλύτερο». **Αυτό ουσιαστικά δεν απαιτεί καμία δεξιότητα.**

Πρέπει να αντισταθείς στην παρόρμηση να ζητήσεις από τον Claude να φτιάξει κάτι και μετά να νιώσεις καλά από **τη μικρή δόση ντοπαμίνης που παίρνεις**. Πρέπει να συνειδητοποιήσεις ότι μόνο και μόνο επειδή ο Claude έφτιαξε κάτι, δεν πρόσθεσες απαραίτητα καμία αξία. Στην πραγματικότητα, στην αρχή, κάνεις κυριολεκτικά το ίδιο με αυτό που θα μπορούσε να κάνει οποιοσδήποτε άλλος.

Αλλά το να έχεις ένα πραγματικό όραμα, να κατανοείς και να σχεδιάζεις πώς θα ταιριάξουν όλα τα κομμάτια, και μετά να μπορείς να χρησιμοποιήσεις με επιτυχία [την πρακτική agentic coding](/guides/what-is-agentic-coding) για να το φτιάξεις, παρακολουθώντας το, ξέροντας πού πηγαίνει λάθος ή πού θα σου προκαλέσει πόνο αργότερα... **Αυτή είναι μια πραγματική δεξιότητα.**

Κάθε μέρα που χρησιμοποιώ το Claude Code, κάνει πράγματα που μου είναι προφανώς λάθος. Προσπαθεί να με οδηγήσει σε μονοπάτια που κυμαίνονται από υποβέλτιστα έως εντελώς κακά. Αλλά τα κάνει τόσο εύκολα, και κάνει τόσα πολλά σωστά, που είναι δύσκολο να το καταλάβεις στην αρχή. Και καθώς αυτά τα μοντέλα σχεδιάζονται όλο και περισσότερο για να λειτουργούν αυτόνομα, η δεξιότητα του προγραμματιστή έγκειται όλο και περισσότερο σε αυτόν τον ρόλο επίβλεψης και καθοδήγησης.

### Πώς να ανεβάσεις το επίπεδό σου

Χρειάζεσαι **κάποιον να σου διδάξει** πώς λειτουργούν όλα και τα σωστά νοητικά μονοπάτια που πρέπει να ακολουθήσεις. Μετά πρέπει να φτιάξεις πράγματα, να κάνεις λάθη, να δεις τι συμβαίνει όταν ο Claude σε παγιδεύει, και να μάθεις από αυτά. Έτσι ώστε να μπορέσεις να προσθέσεις αξία σε μια εταιρεία που φτιάχνει πράγματα. Πρέπει να κατανοήσεις την τεχνολογία, να κατανοήσεις πώς φτιάχνεται το λογισμικό, να μάθεις να διαβάζεις code για να καταλαβαίνεις τι συμβαίνει, και να νιώθεις αυτοπεποίθηση με όλη τη ροή και τη διαδικασία της δημιουργίας πραγμάτων.

Και το [Jiki](https://jiki.io) θα σου τα διδάξει όλα αυτά. Ακολούθησε το μονοπάτι Learn to Code για να αποκτήσεις τα βασικά του προγραμματισμού, και μετά **έλα να μάθεις να φτιάχνεις πράγματα μαζί μου**. Κατανόησε γιατί χρειάζεσαι το GitHub και πώς λειτουργεί, πώς θα σε προστατεύσει το Cloudflare, πώς να σχεδιάζεις ασφαλή πιστοποίηση ταυτότητας (auth), πώς να φτιάχνεις αποδοτικές βάσεις δεδομένων, πώς να δημιουργείς αστραπιαία γρήγορα front-ends και ατσαλένια back-ends. Μάθε πώς να κάνεις deploy πράγματα ώστε να ανακάμπτουν αν πέσουν. Μάθε όλα αυτά μαζί μου. **Και διασκέδασε πάρα πολύ στην πορεία.**

Τα λέμε μέσα!
