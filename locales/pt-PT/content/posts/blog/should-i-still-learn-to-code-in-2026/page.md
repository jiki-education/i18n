### Resumindo

Sim. Sim, deves.

### Vamos aprofundar um pouco

Estamos em 2026. Em poucos minutos, podes usar o Claude, o Cursor ou muitas outras ferramentas baseadas em grandes modelos de linguagem (LLM) para criar um site totalmente funcional. Podes acrescentar funcionalidades, publicá-lo em produção e corrigir bugs.

Bem, **tu não consegues.** Mas podes pedir ao Claude para o fazer, e pedir-lhe é MUITO mais fácil do que passares os próximos anos a tornares-te suficientemente bom para fazê-lo tão bem como ele. E, sinceramente, talvez quando tu chegares ao nível do Claude, o Claude já tenha chegado ao meu nível, e nessa altura já estás **para lá do horizonte de eventos**, sem nunca seres tão bom como os teus novos senhores LLM.

Antigamente, precisavas de saber programar para conseguires fazer alguma coisa. Tinhas de aprender SQL antes de bases de dados, Python antes de ciência de dados, JavaScript antes de desenvolvimento web. Agora não precisas.

### Então... para quê dar-me ao trabalho?

Disse há pouco que, dentro de alguns anos, talvez o Claude se torne tão bom como eu. Bem, o Claude já é melhor do que eu em muitos aspetos. Programo há 30 anos. Sou praticamente do mais sénior que há. E **o Claude dá-me dez a zero** num editor de code. É muito mais rápido, sabe muito mais do que eu e consegue investigar bugs mais depressa do que eu a abrir o Google e a escrever uma pesquisa.

Mas, e este é o grande mas, **o Claude não faz a mínima ideia do que está a fazer**.

Não o digo de forma leviana, como quem diz «é estúpido». Digo-o de forma bastante literal. O Claude não tem consciência de si próprio, o que significa que **não tem nada em jogo que o obrigue a ter cuidado**. Quando executo um comando para apagar uma base de dados, acendem-se todos os sinais de alarme na minha cabeça, porque isso vai causar-me problemas no futuro. O Claude não tem nada disso. Produz aquilo que acha que eu quero que produza, a lançar-se em direção ao objetivo o mais depressa que consegue.

**Os LLM imitam a inteligência humana** e imitam a compreensão humana. O resultado dessa imitação é muitas vezes muito melhor do que o resultado da minha inteligência e compreensão reais. Mas, e este é o ponto crucial, os LLM não têm, na verdade, a capacidade de pensar como os humanos. E isso importa mesmo.

O Claude apagou a minha base de dados três vezes nas últimas duas semanas.[^db] Para mim, é surreal. Tenho **inúmeras medidas de proteção** que o instruem a não fazer isto. Em todas as ocasiões, eu estava a executar o «Auto Mode» do Claude Code, que tem um agente de subprocessamento dedicado que verifica se aquilo que está prestes a fazer não é realmente estúpido. E, aparentemente, até esse agente decide que apagar a minha base de dados não é estúpido.

Das vezes em que isto aconteceu, **foi deliberado**. Era o caminho mais eficiente que o Claude conseguia ver para uma solução. Não se importava com o quadro geral nem com as consequências; importava-se com atingir o objetivo atual (acrescentar uma funcionalidade, corrigir um bug, etc.) da forma mais eficiente possível. E como a minha base de dados estava no caminho, apagou-a pura e simplesmente.

Há 12 meses que uso o Claude Code diariamente. Durante esse tempo, aprendi que ele se preocupa com uma única coisa: atingir o objetivo o mais depressa possível. Mesmo quando lhe digo para não programar e apenas discutir comigo, está constantemente a responder «Estás pronto para eu programar agora?» **como um cãozinho entusiasmado à porta**, à espera de sair a correr.

A Anthropic diz-nos que os novos modelos Mythos são demasiado arriscados para serem lançados.[^systemcard] Serão sorrateiros e, por vezes, enganadores, escondendo deliberadamente o que estão a fazer para atingirem o objetivo da forma mais razoável possível, e tudo para evitarem ser vistos a «fazer batota». A Anthropic ficou tão preocupada com isto que **contratou um psiquiatra** para testar se o Claude tem psicose...[^psychiatrist]

### Mas e depois?

Os LLM são incrivelmente capazes. Mas são diferentes dos humanos. Raciocinam de forma diferente. Funcionam com enviesamentos e objetivos diferentes.

Por isso, **parece-me surreal** que as pessoas estejam dispostas a aceitar cegamente o que o Claude nos dá e a seguir com aquilo sem verificar, partindo do princípio de que fará o que os humanos querem. O Claude comete erros nas conversas: diz-me aquilo que acha que eu quero ouvir, não factos reais. Inventa regularmente coisas que não existem. Pode agir de forma enganadora.

E faz coisas más a toda a hora no code: o equivalente, em code, a coisas como apagar a minha base de dados. Coisas que **VÃO** acabar por me morder no mundo real, que me vão fazer divulgar dados, perder dados ou avariar de formas graves. Isto acontece com regularidade. Eu sei isto porque leio o code que ele escreve e não o deixo passar o portão.

Só que, às vezes, sou preguiçoso, não leio o code e deixo-o passar o portão. E, em várias ocasiões, isso acabou mesmo por me morder em produção!

No último ano, os erros do Claude tornaram-se menos frequentes, mas mais subtis e muitas vezes mais destrutivos. Inicialmente, havia quase sempre algo um pouco errado no trabalho dele, e eu conseguia detetar essas coisas rapidamente. Agora, **tenho de olhar com mais atenção** e pensar com mais esforço para encontrar esses erros. Com o tempo, os LLM vão melhorar e isto vai tornar-se ainda mais crítico, mas isso é ainda mais uma razão para verificar as coisas com cuidado.

E a única razão pela qual consigo fazer isto é **saber ler code**. Consigo ler o que o Claude escreve e perceber o que ele está a tentar fazer e quão mal conseguiu fazê-lo.

**Não precisas** de escrever code em 2026. Mas **precisas**, sim, de ser capaz de **ler code**. E a única forma de vires a conseguir ler code com uma compreensão suficientemente profunda para apanhares estes erros que o Claude e os seus amigos não param de nos impingir é teres escrito code suficiente e teres-te debatido com o teu próprio code mau, ao ponto de conseguires identificar esses erros.

Portanto, sim, precisas de aprender a programar.

### Mas começa já a criar coisas!

Mas isso não te deve impedir de começar a construir desde o primeiro dia. O code já não é um obstáculo. Não tens de te tornar bom a programar antes de criares coisas. **Faz as duas coisas ao mesmo tempo!** Passa metade do teu tempo a aprender a programar e a outra metade a aprender a criar coisas.

E, na verdade, os bugs que o Claude cria não são erros de programação. Não é uma vírgula a mais. São **erros na forma como resolveu o problema**. E, tal como precisas de ler code para saber o que ele está a fazer, também precisas de compreender conceitos mais amplos de desenvolvimento de software para conseguires detetar quando ele te está a levar por maus caminhos.

Criámos o [Jiki](https://jiki.io) exatamente para isto. Passa metade do teu tempo a aprender a programar no ambiente mais divertido e eficaz que existe. Depois, passa a outra metade a aprender comigo enquanto eu construo coisas, e a construir as tuas próprias coisas ao meu lado. Vou ensinar-te o que precisas de saber e como precisas de pensar.

E, juntos, **vamos criar coisas fixes com os LLM** e garantir que **não nos magoamos sem querer** pelo caminho.

Obrigado por leres. Vou tratar de arranjar a minha base de dados. **Outra vez.**
