## 簡介

到這個階段，我們假設你已經安裝好 OpenCode 或同類工具了。如果還沒，請先跟著我們的[安裝代理式程式設計平台](/guides/installing-an-agentic-coding-platform)指南做。

你可以不懂背後的原理，就開始用代理式程式設計工具，就像你可以不知道離合器的作用也能開車一樣。但多懂一點，差別很大。它能說明為什麼工具有時看起來很聰明、有時又讓人一頭霧水，為什麼有些東西要付費，以及怎樣才能得到好上許多的結果。以下就是值得你認識的幾個概念。

## 模型

**模型**（或稱 LLM，也就是「大型語言模型」）才是真正的 AI。像 OpenCode 和 Claude Code 這類工具本身並不具備智慧，它們只是外殼：負責收集你的請求和程式碼，送給模型，再依照回傳的內容行動。模型才是「大腦」。

模型非常多，出自各家不同的公司，其中有 3 個差異對你來說很重要：

- **能力。** 越大、越新的模型，越擅長理解混亂的問題、寫出正確的程式碼。最頂尖的那些（常被稱為「前沿」模型）明顯比其他模型聰明。
- **速度。** 較小的模型回應較快。遇到簡單的問題，用快速的模型通常體驗更好。
- **成本。** 最好的模型，執行成本可能比已經相當夠用的模型高出 50 倍。這就是免費方案會採用較小或促銷性質模型的原因。

沒有永遠的「最強模型」。排行榜每隔幾個月就會重新洗牌，這也是我們推薦你使用能自由切換模型的工具的其中一個原因（在 OpenCode 裡，輸入`/models`）。

## Token

模型不是逐字或逐詞閱讀，它們讀的是 **Token**：一小塊一小塊的文字，平均大約等於四分之三個英文單字。「Understanding」是一個 Token，「Misunderstanding」可能是三個。你送給模型的一切都會被切成 Token，它寫出來的內容也是一個 Token 一個 Token 地回傳。這就是為什麼你看到的回應會像流水一樣一段一段冒出來，而不是一次全部出現。

Token 之所以重要，有一個很重要的原因：**它們就是你要付費的東西**。模型的價格以每百萬個 Token 計算，不論是模型讀進去的（「輸入」）還是寫出來的（「輸出」）。當代理讀取你 5 個程式碼檔案，那可能就是好幾萬個輸入 Token。這就是免費方案會有額度限制的原因，也是為什麼讓代理處理一個大專案，會比回答一個簡單的問題來得貴。

## 上下文視窗

模型沒有記憶。你每送出一則訊息，工具就會把_到目前為止的整段對話_，再加上代理讀過的所有檔案，從頭再送一次。模型的**上下文視窗**，就是它一次能接收的最大量：它的工作記憶，以 Token 為單位計算。

由此可以得出 2 件很實際的事：

- **長時間的工作階段會退化。** 對話越長，上下文就塞滿了先前的繞路和過時的檔案內容。當上下文被塞爆，模型專注的能力會明顯下降。代理在漫長工作階段的後段開始犯一些愚蠢的錯誤時，通常不是它變笨了，而是它快被淹沒了。
- **重新開始不用成本。** 開一個新的工作階段，用乾淨、敘述清楚的請求重新出發，往往比在亂糟糟的舊對話裡硬撐更好。別對你的對話紀錄太有感情。

## 提示詞

你寫給模型的任何內容，都是你的**提示詞**。在代理式程式設計裡，最能讓你事半功倍的技能，就是寫出好的提示詞。「幫我修好程式碼」和「這個資料夾裡的測試跑出這則錯誤訊息，而我預期這個函式會回傳 5，不是 3」之間的差別，就是代理在猜、還是真的知道的差別。

好的提示詞會講清楚 3 件事：你想達成什麼、實際上發生了什麼、你已經試過什麼。就跟同事來請你幫忙時，你會希望他講清楚的一模一樣。

## 代理迴圈

代理和聊天機器人最大的分別，就在於**迴圈**。你交給代理一項任務，它不會只是回答，而是會動手做：

1. 它判斷自己需要知道什麼，並使用**工具**（讀取檔案、搜尋、執行指令）去查出來。
2. 它做出一項修改。
3. 它檢查自己的成果，通常是執行你的程式碼或測試。
4. 如果哪裡失敗了，它就帶著新的資訊回到步驟 1。

觀察這個迴圈本身就很值得學習：它相當程度地呈現了有經驗的程式設計師實際的工作方式。調查、改動一個地方、驗證、重複。在這個迴圈進行的過程中，你的工作是監督。工具在做任何重要的事之前，都會先徵求你的同意，你應該仔細讀它打算做什麼，而不是反射性地什麼都按同意。

## 幻覺，或者說：模型有時會很自信地搞錯

模型了解事情的方式和你不同。它們產生的是看起來最合理的回答，而有時候，看起來最合理的回答根本就是錯的：不存在的函式、從來沒有過的設定、聽起來滴水不漏但其實不正確的說明。這就叫做**幻覺**，而且就算是世界上最好的模型，也無法完全擺脫它。

防範的方法和專業人士用的是同一套：**絕不輕信，凡事驗證**。把程式碼跑起來。在接受修改之前先讀過一遍。如果某個說明很重要，就請模型指出它是根據哪一行程式碼。代理發生這種情況的機率遠比聊天機器人低，正是因為它們的迴圈會實際執行程式、看到真實的結果，但驗證的習慣，你應該從第一天就開始培養。

## 隱私

還有一件事值得知道，尤其是在免費方案上：免費模型之所以免費，通常是因為背後的公司正在蒐集對話，用來改進他們的模型。用在學習練習上，這是很划算的交易。但請把你送給免費模型的任何內容，都當成可能公開：不要放密碼、不要放個人資訊，等你日後進入職場，也別在沒確認公司規定之前，就送出公司的私有程式碼。
