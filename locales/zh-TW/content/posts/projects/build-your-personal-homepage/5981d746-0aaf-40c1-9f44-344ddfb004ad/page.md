## 前言

歡迎來到這個新系列的第一集。這個系列要看的是怎麼使用代理，以及在寫程式這件事已經大幅改變的現代，怎麼用大型語言模型來打造東西。這些年來我們幫 Exercism 辦過很多次類似的直播，但這是 Jiki 第一場正式的 Learn to Build 直播。

我先說明這個系列是什麼、今天具體要講什麼、整個系列會涵蓋哪些內容，還有它適合誰。我就從最後一個問題開始吧。

## 這個系列適合誰

這個系列其實是給兩群人的。第一群是完全沒寫過程式、剛踏進這個世界、只想趕快入門並搞清楚要怎麼開始學的人。但它也適合另一群人，可能是經驗豐富得多的人，甚至是資深開發者，他們還沒真正接觸正在發生的代理式程式設計變革，想了解現在到底怎麼回事、看看實際操作、一起討論，並且對這一切建立真正的理解。所以你可以在這個光譜上的任何位置：可能今天是你寫程式的第一天，也許你今天早上才決定要學寫程式，找到了 Jiki，然後就來到這裡；也可能你是非常資深的開發者。

在這個系列裡（之後會有好幾個系列），我會假設你什麼都不知道。所以如果你是資深開發者，我講的很多東西你大概早就瞭若指掌，可能會覺得有點無聊。如果今天是你的第一天，我講的內容應該不會預設你已經懂什麼。可能有些東西你會聽不太懂，但我是把這一集當成為你而做的。而如果你比較資深，卻還沒試過這種新的寫程式方式，這一集對你一樣會有幫助。

我會帶你稍微了解一下，用這種方式寫程式是什麼意思。我會先示範幾個我現在剛好需要在 Jiki 上處理的問題，把它們修好，算是暖身。接著我們會討論一些常用的術語，以及這些東西怎麼互相搭配。然後我們就真的動手做點東西：做一個新的個人首頁。

這是我想鼓勵每個人都去做的事：幫自己做一個新網站。可以是你的個人首頁，也可以是別的東西。也許就用程式碼做一份履歷，隨便什麼都行。看完這一集之後，把你在這裡看到的東西付諸實踐，自己動手試試看吧。

我會使用 Claude 和一些比較進階的工具，但我也會示範如果你完全沒錢花在這上面，要怎麼做到同樣的事。如果你想免費使用代理，我們也會一起來看看。

## 抓出大型語言模型犯的錯

我要切換到 Jiki 的論壇，看看我稍早注意到的一件事。這些是跟翻譯有關的各個主題，你會發現大部分主題的語言名稱旁邊都有一面國旗。一面荷蘭國旗、一面德國國旗。而土耳其語旁邊放的是一隻火雞（英文的火雞 turkey 和土耳其 Turkey 是同一個字）。這大概有點種族歧視的味道，我們等一下可能得處理一下。不過我看到的是印尼語那個。這些表情符號全都是 Claude 選的。而在這裡，它顯然是自己捏造了一個表情符號，或是用了一個根本無法顯示的表情符號。

![Jiki 的論壇上列出的翻譯主題。土耳其語旁邊是一隻火雞表情符號而不是國旗，印尼語則顯示一個壞掉的 :garuda: 表情符號。](/images/projects/build-your-personal-homepage/setting-up-the-project/forum-language-flags.webp)

我想從這裡開始，因為這是真實發生的事。我在開直播前兩分鐘才看到的。當你使用這些大型語言模型和代理時，你會很常遇到這類狀況。它們會捏造東西。它們以為這裡有一個表情符號，但在這個網站上根本不能用。它們應該放一面土耳其國旗，結果卻真的放了一隻火雞。

這種錯誤對我們人類來說非常明顯。我們一眼就能看出來，它們會跳出來讓你看到，我們也會暗自偷笑一下。令人擔心的是，大型語言模型在這裡做決定的方式，跟它在其他地方做決定的方式是一樣的。而且這還是最強大的模型。這是 Fable，就是那個聰明又危險到被美國政府禁止的模型。但它還是會用火雞來代表土耳其國旗，也不見得知道這可能會惹到某些人。當然，它也可能只是很有幽默感。我不確定。

這些是看得見、很明顯的問題。想像一下，這些大型語言模型在背後還犯了多少其他小錯，或者應該說，做了多少不好的決定。接下來的一年，甚至許多年裡，我們會持續做這些直播，大型語言模型也會不斷進步。但我希望你馬上知道、而且真正內化的一件事是：它們並不是什麼寫程式之神，不是你隨便丟東西給它們，它們就能全部做對。它們一直都在犯錯。有些錯誤很明顯又好笑，有些則不然。如果你想成為現代的軟體開發者，你工作中很大一部分就是找出這些錯誤。我指的不是找出它們把土耳其國旗換成火雞這種事，而是找出它們在觀念上的錯誤：它們提出的想法和做法中，那些感覺不太對勁、不太合理的地方。

### i18n 是什麼意思？

它是 internationalization（國際化）的意思。18 是 i 和 n 之間的字母數量。這是一種簡寫。

## 代理式程式設計一次看懂

我們來看看實際做一點代理式程式設計是什麼樣子。就拿印尼語那個表情符號壞掉的詞彙表來說吧。我要截個圖，切到我的終端機，然後進入 Claude Code。等一下我們會談到要怎麼設定這些東西。它現在看起來可能有點嚇人，黑底綠字的，但我們之後都會講到。

我想給你看的是這個。我可以把圖片拖進來，然後說「修正錯誤的表情符號」。接著它就會開始運作，思考並做很多事情。我們可以看看它在做什麼。它在執行指令。它在試著搞清楚發生了什麼事。為什麼這面國旗是錯的？這面國旗代表什麼？這是怎麼出現的？現在它開始讀一些腳本了。這是建立論壇語言分類的腳本，也就是它當初建立這個分類時執行的腳本。它現在正在翻看自己做過的所有事情的歷史紀錄，試著找出問題是什麼時候出的、怎麼出的、為什麼會出。它在讀各種檔案，執行各種指令。你可以看到數字一直增加，它正在執行第四個指令，以此類推。

![終端機裡的 Claude Code 正在處理「Fix the incorrect emoji」，搜尋模式、讀取檔案並執行 shell 指令。](/images/projects/build-your-personal-homepage/setting-up-the-project/claude-code-fixing-emoji.webp)

然後它說它找到了。正確的表情符號應該是印尼國旗，而不是 `:garuda:`。它接著執行了某個東西來更新這個分類。現在如果我們回到論壇，把這個打開，你會看到它已經修好了。現在顯示的是一面印尼國旗了。

![論壇上的印尼語詞彙表主題，現在顯示正確的印尼國旗。](/images/projects/build-your-personal-homepage/setting-up-the-project/indonesian-flag-fixed.webp)

這就是代理式程式設計的精髓。我們說了「做這一件事」。它就去做了。它執行了這些不同的指令，讀了一些文件，在背景做了一大堆非常複雜的事，包括一些看起來很複雜、寫起來會非常痛苦的 bash。除非你是 Exercism 的維護者，那對你來說就很簡單。但對我們這些凡人來說，要寫出來可能有點複雜。它仔細翻找，試著找出是什麼時候出錯的。它讀了檔案的歷史紀錄，找到印尼語的那筆資料和一些日誌。它讀了我給它的規則，找到一些讓它能夠去更新論壇的變數，搞清楚哪裡出錯，很簡短地跟我討論了一下，然後就去把那個東西更新好了。

我就是這樣打造 Jiki 的。現在很多軟體開發者，我會說大概是現今大多數的軟體開發者，都是這樣工作的。我們發現了一個像這樣的問題。我們注意到它，也許是別人透過工單回報的。然後我們把它交給像 Claude 這樣的工具，或是外面眾多其他模型之一，這部分我們等一下會講到。它們會跑完這個複雜的多步驟流程，然後修好這個 bug。

當然，這個 bug 顯然非常簡單。只有一個頁面，放錯了一個表情符號。它應該是這個表情符號，卻放了另一個。所以它能很快修好。但這整套流程真正厲害的地方，是在我們不只是要修一個小東西的時候。像是我們在開發一個新功能，或是在對某個非常複雜的東西除錯。那代表要讀上百個檔案，然後還需要寫入一些檔案。

## 聰明地控制成本

在我們換另一個例子之前，我先給你看一樣東西。我可以在這裡輸入 `usage`，usage 會告訴我們背後發生了什麼事。你可以看到，Claude 從頭到尾花了 52 秒完成這件事，花費是 37 美分。我用的是 Claude Max，這代表我在各種模型上都有非常大的額度。所以那 37 美分其實不會另外向我收費，它已經包含在我每月的訂閱費裡了。

![Claude Code 的用量畫面，顯示修正表情符號總共花費 0.38 美元、API 時間 52 秒。](/images/projects/build-your-personal-homepage/setting-up-the-project/claude-code-usage.webp)

但既然我們開始聊這些，我希望你馬上意識到一件事。剛才整個找出問題並解決的過程花了 37 美分。如果我想的話，我其實可以直接到論壇上自己編輯那個主題。我可以選取表情符號，輸入 Indonesia，然後點一下國旗。那樣就不會花我 37 美分。想像一下我身為開發者做的每一件事，不管我們一天寫幾個小時的程式，我們大概都應該聰明一點，想清楚哪些事情值得動用這種超強大的智慧，哪些事情自己手動做就好。

對那些沒有付費訂閱 Claude Max、手頭也不寬裕的人來說，這點尤其重要。我會示範怎麼免費做到這一切。但使用免費方案時，你的用量會有限制。這個限制其實相當大方，已經足夠你做所有需要的事。但我希望你養成一種心態：不要把用量浪費在自己能手動完成的事情上。自己去調查、搞清楚發生了什麼事、在過程中學到一點東西，然後再去修好它，這樣對你好得多。這是你學習的最佳方式。如果你開始什麼事都丟給它，我們就麻煩了。

我再給你看一樣東西。這會顯示你每個月的用量。這是我上個月的數據。就像我說的，我用的是 Claude Max 方案，所以每個月只付固定的 200 美元。但如果我沒有用 Claude Max，而是直接按用量付費，這個月會花掉 35,000 美元。這個月我用了 30 億個 token。等一下我們會講 token 是什麼。但你可以看到，帳單很快就會堆得很高。

### 那 Ollama 和其他本地模型呢？

那些也可以用。如果你的電腦夠強，能跑本地模型，例如一台好的 MacBook，或是一台配備好 GPU 的 Windows 電腦，你就可以在自己的電腦上跑模型，而不用把資料送到 Claude、再等 Claude 把資料傳回來。不過速度會慢非常多。剛才那個花了 52 秒的任務，可能會變成 5 分鐘，甚至半小時。就算是在最頂尖的機器上，速度也會比用 Claude 或其他服務慢上 10 倍、20 倍、30 倍。

### 有時候請一位初階開發者，會不會比付錢用大型語言模型更便宜？

因為我訂閱了 Claude Max，一個月 200 美元，所以我使用這一切的總成本就是一個月 200 美元。一位初階開發者的成本會是這個的 10 倍。而且我通常會同時開大概六、七個 Claude。所以如果這個 Claude 跟一位初階開發者一樣厲害，那我就同時有六、七位初階開發者，在不同分頁裡各自做不同的事。在現在這種情況下，請人手動寫這些程式碼在經濟上已經完全不划算了。

不過你能從中受益的地方，也就是你身為初階開發者能展現價值的地方，在於：如果你能同時操作六、七個 Claude，用它們來處理比較直接、比較基本的任務，那你就能為公司帶來巨大的價值。我身為開發者的極限，大概是同時跑五、六個，而且我還是花很多時間在思考和閱讀。只要認真做這件事、真正思考正在發生什麼，每個人都會在這個程度碰到上限。所以如果你今天想進入科技業，你能展現價值的地方，就是學會怎麼駕馭這些 Claude、這些其他模型、這些大型語言模型、這些代理，以及怎麼給它們下提示、賦予它們能力，並用合理又有效的方式審查它們的成果。

## 啟動一個新語言

這就是我們的起點。現在你對這些東西怎麼運作有了一點了解。我們聊天的同時，我要再啟動另一個任務。我打造的其中一樣東西，是一個「啟動新語言」的指令，用來把 Jiki 翻譯成不同的語言。論壇上已經有啟動好的巴西葡萄牙語了，但我想啟動歐洲葡萄牙語。我直接按下執行，然後我們來稍微看一下。

這個指令會去產生各種資料，包括一份指南、一份詞彙表和其他東西，讓我們能把網站翻譯成葡萄牙語。你可以在論壇上看到土耳其語的那份。那就是它產生並建立的詞彙表，列出了所有我們翻譯成土耳其語的術語。

這個代理現在正在努力工作，要把這件事做好。它會派出其他代理。我們有一個主要代理負責整件事，它會派其他代理去研究葡萄牙語的正確術語。它會叫它們去看 Mozilla 的文件和 Microsoft 的文件，找出大家用的是哪些術語。它大概也會去看 Duolingo 和其他一些網站。然後它會回來向我報告一大堆它找到的資料，並問我一些問題。

趁它在忙的時候，我想稍微看一下我剛才執行的那個指令，也就是 Bootstrap Language。這就是 Claude 正在做的事，這些是 Claude 正在遵循的指示。最上面有一小段內容，只是給 Claude 的執行說明。其他所有內容都是你我也能讀懂的資訊，說明了整個過程在做什麼。

我們告訴 Claude 要啟動一個新語言。我們告訴它必須研究這個語言的書寫方式、跟我確認只有我能做的決定、參考這些指南，並以匈牙利語作為基礎，只是因為那是我們最先處理的語言。Aron 是我們這裡的前端開發者，他是匈牙利人。接著有一大堆它要依序完成的階段，還有它要做的一些檢查。你可以看到，我們首先要它檢查這個語言是否已經存在。如果已經存在，就停下來並回報。你會看到它做的第一件事就是說「我先檢查這個語言是否已經存在」。檢查通過了，它不存在，於是它繼續往下。

接著它會去讀一些檔案。它讀了這個規則檔、這個語氣檔和其他一些資料，把這些內容全部載入到它的記憶裡。等一下我們會談到這到底是什麼意思。所以現在它手上有了所有這些資料，所有我寫的那些大型文件，包括規則、要用什麼語氣說話等等。

然後它就去做研究。我給了它各種規則。避免被大型語言模型產生的內容汙染。我不希望它去讀一堆其他大型語言模型已經寫好的內容。我希望它主要只看 2022 年以前的東西，並在使用那些內容之前先確認日期。它會交叉比對多個來源。我要它保持懷疑、坦然面對不確定性，然後去找各種東西。大家用的是什麼比喻？正式程度和語域是怎樣？然後它會把這些整理成某種結構，停下來跟我討論。它會說明它發現了什麼，問我一些問題，提出一些關鍵術語。等我同意了、我們討論過之後，它就會去寫一份詞彙表和一份指南，把它們整理好，然後建立論壇貼文。它有能力進到 Jiki 論壇建立那篇貼文，接著也會建立詞彙表的貼文。那是兩篇不同的貼文。

這就是我打造的指令，它可以照著執行。我們可以看到它在背景持續運作。你看，它現在正在回報研究結果。這是它建議稱呼學習者的方式：我們應該用非正式的「tu」，這是稱呼學習者時溫暖又日常的方式，而不是另一種正式的語氣。然後它請我做一些決定。我同意這樣嗎？它應該沿用巴西葡萄牙語的慣例嗎？它列出了一些它選好的術語。到了這一步，我可以一一看過，然後說：好，這些決定我都同意，你的預設值我也都接受。然後它就會繼續做下去。

### 指令和技能是同一種東西嗎？

對，它們是一樣的。每家大型語言模型公司對這些東西都有各自不同的叫法。

## 代理與模型

我想請大家先停一下，想想剛才到底發生了什麼事，因為這是理解兩者差異的關鍵：一種是你打開 Claude 應用程式或 ChatGPT 跟它對話，另一種則是像這樣使用代理式程式設計。

當你在使用者介面裡跟 Claude 對話時，你是在問一個問題，實際上你只是在跟一個代理說話，它也許會去查點東西，然後回來繼續寫。這很像是你和一個人、一個代理之間的對話。但當你用這種代理式程式設計的模式工作時，背後實際發生的是我們會產生很多個代理，讓它們去做不同的事。我們會有負責研究的代理、負責規劃的代理、負責建構的代理。我們也可以打造自己的代理，例如用特定方式測試東西的代理，或是檢查東西是否符合特定標準的代理。而通常我們在對話的那個代理，就是負責管理所有其他代理的那一個。

這些代理可以使用不同的模型。所以現在正好可以來聊聊模型。你肯定常常聽到這個詞，大概也很清楚模型是什麼，但我還是快速解釋一下。

不同的公司，像是 OpenAI 或 Anthropic，都有各自不同的模型，而模型就是大型語言模型運作的底層機制。它是用一定數量的資料訓練出來的，以一定的速度運作。所謂的前沿模型，就是最頂尖的模型。以 Anthropic 來說，目前就是一個叫 Fable 或 Mythos 的模型。這些模型比較慢、比較貴，但非常強大。在另一端則是 Haiku，它是一個快得多的模型。它的執行成本大概便宜 50 倍，速度也快很多，但推理能力沒那麼好。中間還有 Sonnet 和 Opus。所以一共有這四個模型，而所有不同的供應商也都有各自不同的模型。有些非常高階的模型超級聰明，有些則沒那麼聰明，但快得多。

對一個基本任務來說，比如我們剛才看的那個任務，像是「為什麼這面國旗是錯的」，Haiku 和 Fable 的表現不會有任何差別。但如果你用 Fable 來做，你會多花 50 倍的錢。所以我們要一直留意的一件事，就是哪個模型適合這個任務。這能讓事情跑得很快，讓品質維持在我們真正需要的程度，也能壓低成本，這一點也很重要。

當你執行一個代理，而它又去執行多個其他代理時，它們也一直在做這個判斷。如果它們派出代理去做簡單的事，就會用低階模型。如果它們派出代理去做非常複雜的事，就會派出 Fable。

## 努力程度

我們還有「努力程度」這個概念。努力程度就是模型願意付出多少努力。那麼努力到底是什麼意思？這些模型的運作方式，是自己跟自己對話。它們會進行一段很長、持續不斷的對話。如果你用過 Claude 或 ChatGPT，應該看過「顯示思考過程」之類的選項，你可以看到模型在跟自己對話。它們在做的就是推理：先把自己認為可能的情況輸出出來，然後在這個基礎上繼續推進。

當我們在 Claude 的世界裡（其他工具也一樣）談到努力程度時，意思是：你要跟自己對話多久，才回來給出答案。低努力程度的意思是不要怎麼跟自己對話，直接給我們你想到的第一個答案。高努力程度的意思是多跟自己對話。高努力程度的好處是，Claude 實際上會先說出它腦中浮現的第一個想法（這個比喻不太好，總之就是它最先想到的東西），但接著它會再針對這個想法推理一次，看看合不合理。然後它會再加上第三層，再針對整體推理一次，看看合不合理。然後再加上第四層。它會一直針對自己說的內容推理下去，直到達到它滿意或被說服的程度為止。而在低努力程度下，它會直接告訴你答案。那個答案可能是錯的，也可能沒錯。它的思考沒有經過任何驗證。

所以我們有兩個軸向。一個是模型的品質：Fable、Opus、Sonnet、Haiku。另一個是模型要付出的努力程度：低、中、高、特高，而且還可以一直往上加。通常越往上，供應商收費就越高。

在 Claude Code 裡，只要輸入 `/model` 就能切換模型，然後可以在 Opus、Fable、Sonnet 或 Haiku 之間選擇。我們也可以選擇努力程度：low、medium、high 或 max，還有一些閃閃發亮的 max 選項，以及 ultracode，會出現一些很漂亮的動畫，看得出來有人在上面下了很多功夫。

我通常會把 Opus 搭配 medium 當成標準設定，大部分的事情都用它。我做的大部分事情，都需要像 Opus 這樣的模型好好思考，而我覺得 medium 的努力程度剛好平衡。但我對這件事非常有意識，每次開始一個任務時，我都會想清楚要用哪個模型。這件事簡單還是困難？整個過程需要投入多少努力？

### 我們要怎麼記得哪個模型最適合哪個任務？

這個你會隨著時間慢慢學會。一個簡單的經驗法則，是問問自己：這件事對你來說有多難？這件事真的很簡單嗎？像是在論壇貼文上換一面國旗那樣？那就非常簡單，Haiku 用低努力程度就能搞定。你要它做的事，是不是讓你覺得複雜到腦袋打結？那就換一個更好的模型，或是提高努力程度。

Fable 非常擅長處理長時間執行的任務。舉個例子，我昨天開了一個工作階段，把我們所有的影片（之後我會找時間講講我是怎麼製作這些影片的）裡的英文全部抽取出來。任何寫在畫面上的英文，我都把它從影片裡抽出來，改成一層疊加的圖層，這樣我之後只要把它換成別的語言，再重新匯出影片，畫面上就會是另一種語言。

我讓 Fable 來做這件事。我給它一個任務，讓它為每部影片各派出一個 Fable 代理，所以我同時有 32 個 Fable 在跑。每一個都把影片從頭到尾看過一遍，找出所有文字。它們截了圖，然後更新圖片，把文字從圖片上移除。接著它們找出那段文字原本用的是什麼字型、字級、字重、字距、行距、字偶間距，以及可變字型的所有這類設定。然後它們把文字寫回畫面上正確的位置，再反覆截圖比對，直到兩張截圖完全一致，連一個像素都不差。我有一個 Fable 負責規劃整件事、做研究、檢視內容、寫一些文件，然後有一個負責統籌的 Sonnet，專門去派出更多 Fable 來完成所有這些工作。整件事大概花了三個小時，成本大約 400 美元。同樣地，這包含在我的 Max 訂閱裡，但如果不是的話，大概要花 400 美元。而它基本上把所有影片都處理到可以直接使用的狀態了。

在那種情況下，我知道那是一個相當複雜的任務。我之前試過用 Opus 來做，但 Opus 做不到。對 Opus 來說太複雜了，所以我知道需要 Fable。

### 前沿模型就像旗艦手機嗎？

對，完全正確。它們比較聰明、比較好，但也比較貴，而且通常比較慢。你要記得，今天的前沿模型，就是一年後的便宜模型。這件事現在已經成真了。Haiku 就相當於去年的前沿模型。所以 Haiku 雖然是另一端的便宜模型，但已經好到能處理大量的寫程式工作了。只有當你真的在做一件前一代模型（像是 Opus）做不到的事情時，才需要那個昂貴的模型。你真的只應該在特定情況下才動用前沿模型。

### 對專家來說，花錢讓別人寫程式而不是自己寫，不會很挫折嗎？

我一個月付 200 美元。雖然這是一筆不小的錢，但以它帶來的額外生產力來說，這個價格很低。我覺得我現在至少比以前多了一半的生產力，產出是以前的 1.5 倍。我不知道我在就業市場上的薪水會是多少，因為我從來沒上過班，但如果用這個當標準，我想它幫我省了一大筆錢。所以 200 美元算是很便宜。如果我每個月得付 2,000 美元，那對我來說大概就不值得了。

它很多時候會讓人超級挫折嗎？會。但我發現，它只是讓我往上提升了一個抽象層次。以前有很多程式我不得不寫，而那些對我來說真的很無聊。對初階或中階開發者來說可能很有趣，但對我來說超級無聊。現在我不用再寫那些了，也不需要管理一位初階或中階開發者。我可以非常輕鬆地把那些事做完，而不用去管理其他人，這代表我還能在其他方面保持生產力。所以對我來說，整體的好處是值得的。

但我覺得對很多開發者來說，寫程式變得沒以前那麼好玩、沒那麼享受了。但這也就是現實。我們沒有選擇。也許有些人在工作上還有不這樣做的餘裕。但如果快轉 10 年，我不認為還有多少人擁有這種餘裕。所以如果你想讓自己面對未來不被淘汰，或是想在這個產業裡取得領先，我認為把這件事做好就是關鍵。

## 權限與自動模式

回到翻譯的任務，它現在已經完成了。我們現在有一些已經提交的檔案。如果我們回到論壇，看看有沒有新的貼文。啊，這就有意思了。發文到公開論壇的動作被擋下來了，因為我把它設成了自動模式。

它的運作方式是這樣的：它會嘗試做一些事，然後另一個大型語言模型會監看它在做什麼，並檢查這些事看起來是不是我明確說過可以做的。只要它要把資料發送到其他網站，或是做任何類似的事，就需要我明確表示同意。而因為我把它留在自動模式，讓它自己一直跑，它沒有問我同不同意，所以這個動作就被擋下來了。它問我：「你要我繼續建立那篇論壇貼文嗎？」我說好，它現在就會真的去做。這是最近兩、三個月才出現的變化之一。我們現在幾乎有了一個負責監督的大型語言模型，它讓更多事情可以自動發生，但也會試著阻止有風險或危險的事情發生。

所以現在如果我重新整理，你看，現在有詞彙表了。這些是它找到並讀過的所有術語，這是它整理出來的所有內容。我們現在有一篇貼文了。

![Jiki 論壇上完成的歐洲葡萄牙語詞彙表貼文，逐一列出術語的翻譯和說明。](/images/projects/build-your-personal-homepage/setting-up-the-project/portuguese-glossary.webp) 如果你會說葡萄牙語，也就是歐洲葡萄牙語，你可以到這裡來，開始告訴我所有錯的地方，然後我們就能開始改進這份詞彙表、一起把它做好。至於會說其他語言的人，我們也有其他語言版本的詞彙表，像是義大利語、土耳其語等等。你現在知道這些是怎麼做出來的了，你也可以自己去做。

## Claude Code、Codex 和 OpenCode

以上就是我對這一切如何運作的整體概覽。接下來我想示範的，是你要怎麼幫自己把這些設定好。

有很多不同的代理和工具可以用。所以我們先把用語講清楚。Claude Code，也就是你剛才看到我在裡面工作的那個視窗，是一個代理式程式設計工具，也可以說是一個代理式程式設計平台。它在你的電腦上執行。通常它是在終端機裡執行，我就是這樣設定的。我們也可以在程式碼編輯器裡執行它，這個我們等一下會看到。它是你和模型之間的入口。我示範過，我可以在 Opus、Sonnet、Haiku 之間切換，也可以切換不同的努力程度。

這一切都發生在你的本地電腦上。你是在你的本地電腦上對話。它會把資料送到 Anthropic，送到他們的某個模型。他們傳回來的，不只是一段出現在畫面上的文字。他們傳回來的是一大堆 Claude Code 能夠解讀並據此行動的指示。他們會說：去這個人的電腦上執行這個腳本。去這個人的電腦上看看這個目錄。去存取那邊的這個網站，然後做點事。所有這些指示都是從 Claude 那裡傳回來的。

所以我們並不是在跟 Opus、Sonnet 或 Haiku 對話。我們是輸入一些文字，而這些文字會跟一大堆其他東西打包在一起。它會跟我們儲存庫裡的程式碼打包在一起，也就是我們寫的、或是被放進去的程式碼。它會跟整段對話的歷史紀錄、我們想達成的目標、我們偏好的工作方式打包在一起。這些全部打包好之後，就會被送到 Anthropic。他們的模型會讀完這些內容，然後帶回一些指示和文字。這些全部會被處理，接著就發生這個循環，也就是代理式循環：它做了某件事，回去找 Claude，Claude 回來說：好，現在做這個。這一切都在我們看不到的地方發生。到最後，它才告訴我們：好，現在完成了。因為某某原因，我們沒辦法發出那篇論壇貼文。你要繼續嗎？整個背後有一個超大的循環在進行。

所以我們要做兩個決定。第一個決定是我們想用哪些模型。我們想在背後使用 Anthropic、OpenAI，還是其他的模型？第二個決定是我們想用哪個工具來互動。如果我用 Claude Code，我永遠都是在跟 Anthropic 的某個模型互動。如果我用 Codex，也就是 OpenAI 的版本，我永遠都是在跟 OpenAI 的某個模型互動，也就是某個 GPT 模型。

我要推薦你使用的是另一個東西，叫做 OpenCode。OpenCode 可以說是 Claude Code 的開源版本，也是 Codex 的開源版本。它是控制整個流程的那一層，也就是裝在你電腦上、負責跑整個循環、管理一切的工具。但它可以跟任何模型溝通。它可以跟 Anthropic 的 Opus 或 Sonnet 溝通，也可以跟 GPT-5 之類的模型溝通。但它也能跟很多免費的模型溝通。OpenCode 本身是免費的，而且它還有一系列你可以使用的免費模型。

安裝好 OpenCode 之後，只要在終端機裡輸入 `opencode` 就能進入。我們可以在很多模型之間選擇。可以選 Google 的 Gemini。可以選我們剛才提到的 Opus，或是 Fable。如果你想支持 Elon Musk，可以選 Grok。還有各種 GPT。DeepSeek，一個出身中國、名氣很大的模型。Qwen，很適合寫程式。還有最上面這些選項，都是免費的。所以如果你沒什麼錢，或是只想試試看，又或是你的公司沒有幫你付訂閱費，你可以免費使用 OpenCode，然後選擇其中一個免費模型。

我會發布一份指南，說明怎麼安裝 OpenCode、怎麼免費設定好，以及這些模型裡哪些可以用。我目前推薦的是 DeepSeek V4 Flash (free)，不過我自己其實沒怎麼試過這些模型，所以你可以自己試試看，看哪個最適合你。

有一點要注意：這些免費模型都不是前沿模型。不過 Big Pickle 是一個神祕模型，所以它有可能是前沿模型，我們也不知道。但其他的都不是前沿模型，不是最頂尖、最好的模型。它們比較接近 Haiku 或 Sonnet 這種等級較低的模型。但以你現在的程度來說，我覺得這其實是一件好事。因為你想走的是一小步一小步的嬰兒步，你不會想要一個超級智慧幫你把所有事情都做完。你想要的是一個能跟你一起工作、一起討論的夥伴，讓你可以一小步一小步地前進，問它東西是怎麼運作的，並從中學習。

## token 與上下文

我來示範一下在翻譯儲存庫裡使用 OpenCode。它對我的儲存庫一無所知。但我可以問它「我們目前有幾種語言？」之類的問題，然後它就會開始處理。這就是 OpenCode 的樣子。左邊是對話區，左下角是我們輸入文字的地方。它在執行時，右邊會有一個區塊。我們可以按 Ctrl+P 叫出各種指令和可以玩玩看的東西。你可以看到它非常快。它只思考了幾毫秒，讀了一些東西，算出答案，回覆說有 14 種語言。如果你反白某段文字，它就會自動複製到你的剪貼簿，這點很方便。

![終端機裡的 OpenCode 正在回答「How many languages do we have so far?」，右邊的上下文面板顯示已使用 10,054 個 token。](/images/projects/build-your-personal-homepage/setting-up-the-project/opencode-ui.webp)

你可以看到它是免費的，所以我們一毛錢都沒花。但我希望你稍微注意一下右邊的數字。我不打算深入解釋大型語言模型的運作原理，因為那是一個很深的坑，不值得我們跳下去。但大型語言模型的基本單位是 token。你可以把 token 想成一個音節。「How」大概是一個 token。「Language」大概是三個 token：lang-u-age，差不多那樣。「DeepSeek」大概是兩個 token。「V4」大概也是兩個 token。

每當你輸入東西時，它會把你輸入的內容，連同它找出答案所需的所有東西，一起送到模型。模型讀完之後回傳，可能會問一個釐清用的問題，雙方來回幾次。這個過程會用掉 token。我們問的是「我們目前有幾種語言？」。這大概是 11 個 token，算上空格可能是 15 個 token。等它讀完、拿到所有需要的東西、送出去、來回跳了幾趟之後，總共用了 10,000 個 token。所以這實際上等於把一篇 3,000 字的文章送給模型，然後拿回一小段回覆。

如果我們問一個比較大的問題，像是「新增一種語言的流程是什麼？」，它就會去讀更多檔案，你可以看到 token 數隨著它讀檔一路往上跳。為了回答這個問題，它又多用了 6,000 個 token，現在已經用掉我們 10% 的上下文了。這個模型的上下文，也就是一段對話中能容納的最大 token 數，大約是 170,000 個 token。

在使用這些工具時，你需要稍微留意這個數字。隨著你用的 token 越來越多，整段對話會變得越來越慢，因為每一次都要把所有上下文傳給模型。如果我再多問一件事，所有這些資訊都會再被送到模型一次。所有先前的對話、所有先前的回答。對話中的每一步，都會把所有東西送出去。

使用免費模型的另一個缺點是，它們能容納的對話量通常比較小。Opus 每段對話可以有 100 萬個 token。這個模型則比較接近 150,000 或 170,000 個。所以你會想要經常開啟新的對話。輸入 `/new` 就能開一段新對話。這會重置你的 token，但你的模型也會因此對剛才發生的事一無所知。所以你要試著養成習慣，針對不同的事情開一段段短短的小對話。

### Aron 和 Nicole 在 Jiki 也是這樣工作的嗎？

對。Aron 做的任何前端工作，幾乎全都是用這種方式。Nicole 在剪輯影片時也一樣。我們所有的影片都是用程式碼寫出來的。我們不是用影片剪輯軟體做影片，而是用程式碼來做，然後她再跟 Claude 一起，從程式碼把所有影片做出來。

### 你會推薦 Mistral 嗎？

Anthropic 以外的模型，我其實都不太了解。我個人每天都只用 Claude。我從來沒用過 Mistral，所以我不知道。我自己的話就只會用 Claude，而且大概只會在不用按 token 計費的訂閱方案下使用。

## 網頁是什麼

我想在這裡稍微聊聊網頁是什麼，以及網頁是怎麼運作的。接下來不管多長的時間裡，我們會做很多 JavaScript、CSS 和各種複雜的東西。但今天我們只做最基本的事。如果你對網站有一點了解，這部分你大概會覺得非常基礎。如果你完全不懂，希望這能幫你為接下來的內容打好基礎。

我們來聊聊一個標準、簡單的網頁是什麼樣子。這裡我們就拿我現有的個人網站來當例子，它非常簡單，就只是頁面上的一些文字。你可以到任何網站按右鍵，選「檢視網頁原始碼」，就會看到像這樣的畫面，一大堆東西。這就是 HTML。

![Jeremy 個人網站的 HTML 原始碼，顯示 doctype、head 標籤、meta 標籤和 title。](/images/projects/build-your-personal-homepage/setting-up-the-project/ihid-page-source.webp)

HTML 最有名的特徵，就是各種東西的開頭有一個小於符號，結尾有一個大於符號。這個就是我們所說的 head 標籤。接著是一些 CSS。CSS 是負責樣式的，這個我們等一下會講。然後是頁面上所有的內容。這是頁首，你可以看到這裡的頁首是紫色的。它裡面有一張圖片。`img` 代表圖片（image），裡面有一個指向圖片的連結。還有一些文字，是我的簡介，然後是更多被分成段落的文字。`p` 代表段落（paragraph）。再多一點資訊，還有一些標題。這是二級標題，這是一級標題。下面這裡是 JavaScript，如果你上過 Coding Fundamentals，應該會覺得有點眼熟。

去年我們辦訓練營、上網頁開發基礎的時候，花了很多時間非常深入地研究這些 HTML，也非常深入地研究 CSS。確保你理解所有不同的標籤和它們的運作方式，也理解 CSS，以及怎麼用它來設定各種東西的樣式。

這就是我認為事情已經翻轉的一個例子。我現在認為，我們應該直接動手做東西，然後再回頭看看做出來的東西，理解它長什麼樣子。以前我會建議你、而且事實上你以前也不得不做的，是從頭開始把這些全部寫出來。但我現在建議的，是直接讓大型語言模型幫我們做出一個非常、非常基本的結構，讓我們拿來用。

## index.html

另一件要知道的事是，有一個由來已久的慣例：一個叫 `index.html` 的檔案，就是網站的第一個頁面。如果你前往 ihid.info/index.html，你看到的基本上就是首頁。規則是這樣的：如果你在網域後面什麼都沒加，它就會去找有沒有一個叫 index.html 的檔案，如果有，就直接顯示它的內容。這個 index.html 是一個非常特別的檔案。它其實沒做什麼神奇的事，它只是一個標準。但傳統上很多網站都是用這種方式來處理。

所以如果你已經打開 OpenCode，可以這樣說：

> 建立一個 index.html，裡面放一個頁面最陽春的基本架構，標題是我的名字 Jeremy Walker，再加上一行關於這個的簡介。

我們在這裡面臨一個分岔點。如果我們想要，也可以說「幫我做一整個網站」，它也會照做。但這樣會發生兩件事。第一，那不會是我們想要的網站。隨著課程推進，我們會去思考那些網站應該是什麼樣子，而且我還會出一個挑戰，要你自己去構思一個網站。這個我們等一下會講。第二，它會一次給你太多東西，你根本學不到什麼。相反地，透過這樣一小步一小步地前進，你才能學會東西是怎麼運作的。

所以我們把這個送出去，這就是它寫出來的東西。現在我們可以在 VS Code 裡把它打開來看。這就是我平常做這件事時的工作流。我的整個網站在這裡，可能有上千個不同的檔案，我讓我的代理去處理這些檔案。然後如果我需要檢查什麼、看看它在做什麼、或是編輯東西，我就在這邊把檔案打開來看。

現在有了這個檔案，我們還可以做另一件事，就是實際用 Chrome 把它打開。只要在檔案上按右鍵，選「用 Chrome 開啟」，你現在就能看到我們剛做好的頁面了。恭喜你！你已經幫自己做出一個個人首頁了。它不是一個很精彩、很好看的首頁，但它確實是一個首頁喔。

## 理解它做了什麼

我希望我們花一點時間，而這也是我希望你一直保持的心態：花一點時間看看這裡到底發生了什麼事。既然你已經做出這個東西，我鼓勵你這樣問它：

> 跟我解釋每個部分是做什麼的。

這個循環不只可以用來叫它做事，也可以用來理解東西，建立你對事物運作方式的知識。這對它來說應該不是什麼太複雜的問題，因為 a) 這是它剛寫的，b) 內容非常簡單。然後它就解釋了。來看看吧。

第一行是 doctype 標籤，它告訴瀏覽器這是一份 HTML5 文件。那這裡實際上發生了什麼事？這個 HTML 是什麼？嗯，這個瀏覽器是 Chrome（當然也有其他瀏覽器）。它知道怎麼讀取 HTML 檔案，並用你看得到的方式把它顯示在畫面上。HTML 是一種規格。它的全名是 hypertext markup language（超文字標記語言）。它看起來就像這樣，有一大堆標籤和一些資訊，而 Chrome 或任何其他瀏覽器都能讀懂這些標籤，並把它們顯示在畫面上。

上面那部分先不用管。只看下面的 body。它放了一個標題和一段段落文字。這個 `h1` 代表一級標題。你可以看到，因為這是一級標題，Chrome 知道要把它顯示得大一點、粗一點。而這個 `p` 是段落，Chrome 知道要把它顯示得小一點。

如果我們想要，也可以在這裡放其他標籤。這是一個無序清單，`ul`，裡面會放清單項目，`li`。自從我開始用 Claude 之後，發生了一件事：我打字變得很不靈光。總之，我們可以把不同的標籤組合起來，這樣就會得到一些項目符號。

所以這就是網頁的構造，也就是網頁的骨架。每一個網頁都是一樣的。如果我們前往 jiki.io 並檢視頁面的原始碼，你會看到它完全一樣，就是一大堆這樣的標籤。你可以看到這裡是一樣的。我們剛才就用了一個無序清單、一個清單項目，還有一個帶著文字、旁邊放了圖示的連結。這就是 HTML。從現在開始直到歷史的盡頭，不管你做什麼網站，你永遠都是在把 HTML 輸出給網頁瀏覽器。

我們把它這麼貼心幫我們整理好的內容讀完吧。那接下來是什麼？我們有 doctype，它說明這是一份 HTML 文件。接著我們說：好，這是我們 HTML 文件的開頭，而這份文件使用的語言是英文。

接下來有兩個部分：head 和 body。

head 裡的第一個東西，是我們使用的字元，我們用的是一組叫做 UTF-8 的字元集。這裡的每一個都是一個字元。我們的意思是，可以使用任何拉丁字母、羅馬字母之類的字元，像這些，也可以在這裡使用表情符號。如果我們拿一個表情符號，直接放進這份文件，然後重新整理，頁面上就會出現一個表情符號。這就是這一行的意思。它是在說：這是你平常會用到的所有字元，這是我們的標準字元集。

還有一個 viewport。這個我們現在先不用管。

然後還有一個 title。這個 title 是 Jeremy Walker。這個 title 就是顯示在分頁最上方的標題。寫程式時，你會常常思考要在那裡顯示什麼標題，這樣當大家開著很多分頁時，就能在上面看到他們想看的東西。我們也可以更改像是網站圖示（favicon）這類東西。你可以看到我們還沒設定，所以那裡沒有圖示。

這個 head 區塊，放的是所有不會顯示在畫面上的東西。任何搜尋引擎可能會看的東西，以及其他類似的東西，都放在 head 裡。而 body 則是下面那塊方形空間裡的所有東西。這裡真的就只是一個標題、一個段落和一個清單。

這就是它的解釋告訴我們的內容。`html` 標籤是根元素。head 是中繼資料。中繼資料的意思就是描述這個頁面的資料，而不是你會看到的東西。charset 是字元編碼，它讓你的表情符號和一些其他語言的字元能夠顯示出來。viewport 我們先不用管。然後 body 就是我們剛才看過的其他東西。

對那些已經寫 HTML 寫了好多年的人，很抱歉這部分對你來說這麼基礎，但你當初也是從零開始學會這些的。

## 你的作業

接下來要思考的，是我們希望自己的個人首頁長什麼樣子。這是一個我希望你花點時間好好想的問題。在這個課程裡，我會常常鼓勵你拿一枝筆和一本筆記本，找個安靜的地方坐下來，離螢幕越遠越好，然後好好思考。

我們要幫自己打造一個個人首頁。這個首頁需要有幾樣東西。它需要有一段關於我們自己和興趣的概述。它需要有一個頁面放我們的履歷。它還會有一個作品集頁面，列出我們正在做的所有專案，然後再連到介紹這些專案的其他頁面。所以隨著時間推進，我們會打造一個大型的多頁網站。大部分的內容我們會在第二集做。今天我們只做這一個概述頁面。但我希望你用紙筆好好想一想，把你希望各個頁面長什麼樣子畫出來。

也想一想你想要什麼樣的風格。去看看其他人的網頁。找找 Exercism 社群裡的其他人。像是以前在我們這裡工作過的 Erik Schierboom，他有一個非常簡潔的主要登陸頁面，還有一個關於頁面，做得很精巧，底部還會跳出一個很可愛的小東西。他放了一些關於軟體的資訊、他去演講過的地方，還有一些對外連結。你可能會從中得到不少靈感。或是看看 SleeplessByte。如果你參加過訓練營，或是從導師那邊，你可能還記得 DJ。這是 DJ 的網頁。所以去找找你感興趣的人，從他們做的東西裡汲取靈感吧。想想你在視覺上喜歡哪種風格。之後我們也會聊聊怎麼製作圖片，以及怎麼用科技來做圖。

多去探索不同人的想法。我自己一直都很喜歡非常極簡的感覺。而為了這個專案，接下來幾天我也會好好想想，我希望自己的新登陸頁面長什麼樣子，因為我也要幫自己做這個首頁。我會思考它要怎麼分區。我想要一個放攝影作品的區塊。我想要一個區塊放我的 podcast、影片和我做過的其他東西。我想要一段簡介，也想要一份履歷。所以我會好好想想這些東西。

你這週的作業，就是去想想這些、把它設計出來，然後開始建構這些頁面的結構。你可以建立多個頁面。我們可以再建立一個頁面，就叫它 my resume，把我們的內容複製貼上進去，刪掉不需要的部分，然後把 title 改成「Jeremy's Resume」。現在我們有了 index 頁面，也可以前往 resume.html，把它當成另一個頁面。

所以，這週要做的是：

- 想想你會想要哪些不同的頁面，以及要在這些頁面裡放哪些不同的內容。
- 安裝 VS Code。
- 安裝 OpenCode，並設定好一個模型。
- 搭配 OpenCode，把其中幾個頁面做出來。

先不用擔心樣式。我其實還不希望你碰那部分。如果你想玩玩看也可以，我永遠鼓勵大家保持好奇心，但我想先教你我認為在現代世界裡最好的做法。絕對不要開始用 JavaScript 框架或其他任何東西。只用最陽春的 HTML 就好，然後我們每一集都會再往上疊一層，讓它變得越來越強大、越來越複雜。這樣你才能理解每一件事是怎麼發生的。

如果你有興趣，可以再多研究一下 HTML。搞清楚有哪些不同的標籤，以及它們分別代表什麼意思。現在要研究東西，可以簡單到只要問：

> 告訴我最常用的 20 個標籤。

然後再問：

> 告訴我它們各自是做什麼用的。

我就是這樣研究東西的。

我們過幾天會進行下一集。到那時候，我希望你已經裝好 OpenCode、裝好 VS Code，也做好一系列的頁面。下一集我們會開始把這些頁面連結起來、加上導覽列、加上一些樣式，還會把它部署到 GitHub 上，說不定還能幫你拿到一個自訂網域，讓你免費在自己的網域上擁有一個個人網站。這週你也可以順便到 github.com 註冊 GitHub。我會發布 VS Code、OpenCode 和 GitHub 的指南，你可以照著那些指南一步步做。

第一集就到這裡結束了。謝謝你的收看。希望你覺得很有意思，也希望你看得開心。如果你對這一集提到的任何內容有問題，歡迎到論壇來。我會在那裡，很期待回答大家的問題、跟大家一起探討。我不見得有所有的答案，我自己也很喜歡學習。所以儘管問你感興趣的任何問題吧。期待在下一集見到你！
