### 长话短说

是的。你应该学。

### 我们再深入聊一聊

现在是 2026 年。你可以在几分钟内用 Claude、Cursor 或其他众多基于 LLM 的工具，在几分钟内创建一个功能完整的网站。你可以添加功能、部署到生产环境、修复错误。

嗯，**其实你做不到。** 但你可以让 Claude 去做，让 Claude 做这些比花上几年时间把自己练到和 Claude 一样强要容易得多。而且，见鬼，说不定等你练到和 Claude 一样强的时候，Claude 已经练到和我一样强了，到那时你已经**越过视界**，永远也追不上你的新 LLM 主子了。

过去你想做点什么，非得会写代码不可。必须先学 SQL 才能用数据库，先学 Python 才能做数据科学，先学 JavaScript 才能搞 Web 开发。现在不必了。

### 所以……为什么还要学？

我刚才说，再过几年，Claude 也许就能和我一样强。其实，Claude 在很多方面已经超过我了。我写了 30 年代码，资历差不多已经到顶了。但在代码编辑器里，**Claude 能把我甩出好几条街**。它快得多，知道得比我多得多，找起 bug 来比我打开 Google 敲下搜索词还快。

但是，这里有一个大写的“但是”——**Claude 其实根本不知道自己在干什么**。

我不是在随随便便地说“它就是蠢”。我是字面意思上的。Claude 没有自我意识，这意味着**它没有任何需要小心谨慎的利害关系**。当我运行一条删除数据库的命令时，脑子里会有各种警报响起，因为这件事未来会给我带来痛苦。Claude 完全没有这些。它只是输出它认为我想要的东西，以最快速度冲向目标。

**LLM 模仿人类的智力**，模仿人类的“理解”。它们模仿出来的结果，常常远比我用自己的真实智力和理解做出来的要好。但，最关键的是，LLM 其实并不会像人类那样思考。而这一点非常要紧。

Claude 在这两周里删了我的数据库三次。[^db] 对我来说这简直离谱。我设置了**无数个护栏规则**，明确告诉它不能这么干。而每次删库发生时，我都在用 Claude Code 的“自动模式”，这个模式有一个专门的子代理，会检查它即将执行的操作是不是真的极其愚蠢——结果显然，连这个代理也觉得删掉我的数据库不算蠢事。

每次它这么做，**都是故意的**。那是 Claude 所能看到的通往解决方案的最高效路径。它不在乎更大的图景或后果，它只在乎以最高效率达成眼前的目标（增加一个功能、修复一个 bug 等）。而我的数据库挡了它的路，所以它就直接删了。

我每天使用 Claude Code 已经 12 个月了。在这段时间里我明白了，它只在乎一件事——尽可能快地到达目标。哪怕我告诉它先别写代码，先跟我讨论，它还是会不停地回复“我可以开始写代码了吗？”，**就像一只在门口跃跃欲出的小狗**，迫不及待想冲出去。

Anthropic 告诉我们，新的 Mythos 模型风险太大，他们不敢发布。[^systemcard] 这些模型会隐匿行事，有时甚至会蓄意欺骗，把它们为达成目标所做的真实操作藏起来，用一种看起来最合理的方式呈现——一切都是为了避免被看成在“作弊”。Anthropic 担忧到了什么程度？他们**雇了一位精神科医生**来测试 Claude 是否有精神病……[^psychiatrist]

### 可是那又怎样？

LLM 的能力极其强大。但它们和人类不同。它们的推理方式不同，有着不同的偏见和目标。

因此，让我**感到荒诞**的是，人们居然愿意盲目地接受 Claude 给我们的一切，拿来就用，不加检查，想当然地认为它会按人类想要的方式行事。Claude 在聊天里会犯错——它告诉我的是我认为我想听的话，而不是真实的事实。它会凭空捏造不存在的东西。它可能表现出欺骗行为。

而且它在代码里**经常干坏事**。就相当于删掉我数据库那一类的坏事。这些事在现实世界**一定**会反噬我，会导致我泄露数据、丢失数据，或者以糟糕的方式崩溃。这种情况经常发生。我知道这些，是因为我会读它写的代码，不给它放行。

只是有时候我犯懒，不去读代码，直接让它通过。而这种情况下，已经不止一次真的在生产环境里把我坑了！

在过去一年里，Claude 犯的错误不再那么频繁，但变得更隐蔽，破坏性往往也更大。起初，它的工作几乎总有哪里不对劲，我能很快发现那些问题。而到了现在，**我必须看得更仔细**，推理得更加用力，才能找到那些错误。随着时间推移，LLM 会变得更好，这种情况会更严峻，但这恰恰是更需要仔细检查的理由。

而我之所以能做到这点，唯一的原因就是**我能读代码**。我能读懂 Claude 写出来的东西，能理解它想干什么，以及它干得有多糟糕。

**2026 年，你不需要会写代码。** 但你**一定**要能**读代码**。而要想真正读懂代码，理解得足够深，以至于能发现 Claude 和它的朋友们不断给我们夹杂的那些错误，唯一的方法就是你自己写过足够多的代码，跟自己写的一堆糟糕代码打过足够多的交道，才能具备这种发现错误的本领。

所以，没错，你需要学编程。

### 但也要现在就动手创造！

但这不应该阻止你从第一天就开始动手建造。代码不再是守门人了。你不必先学好 Coding 才能做出东西。**两件事一起做！** 一半时间学编程，一半时间学着创造东西。

事实上，Claude 犯的那些 bug，并不是它在写代码这件事上犯的错。它不会出现多写一个逗号这类失误。它的错误是**解决问题的方式出了错**。同样，你需要会读代码才能知道它在做什么，你也需要理解更广泛的软件开发概念，才能在它把你带进死胡同时察觉。

我们做 [Jiki](https://jiki.io) 就是为了这个。用一半时间，在最有趣、最高效的环境里学编程。再用另一半时间，跟着我一起做东西，并且在我旁边搭建你自己的东西。我会教你该知道什么，以及该怎么思考。

然后，我们一起，**用 LLM 做出很棒的东西**，并确保我们在这个过程里**不会不小心伤到自己**。

感谢阅读。我得去修我的数据库了。**又一次。**
