До сих пор каждая функция, которую вы писали, по сути справлялась сама по себе и содержала всю логику, нужную для работы.

А теперь давайте посмотрим, как разбивать функции на части: тогда у нас будут маленькие функции, которые работают вместе, а не большие, в которых происходит сразу много всего.

В программировании есть общее правило: каждая функция должна делать как можно меньше. Такое свойство называют единственной ответственностью функции (англ. *single responsibility*). Каждая функция должна заниматься только одним делом, а для отдельных частей этого дела использовать другие функции.

Давайте посмотрим на пример.

Представьте, что у нас есть функция, которая возвращает строку с описанием имени.

Простая версия выглядела бы так. Здесь есть цикл со счётчиком (вы уже писали такие), а потом шаблонная строка, которая собирает результат воедино.

```javascript
function describeName(name) {
  let length = 0
  for (const letter in name) {
    length += 1
  }
  return `This name is ${length} letters long`
}
```

Работает это нормально, но функция делает сразу две вещи: одну довольно общую (подсчёт) и другую очень конкретную (сборку этой строки в определённом формате).

Гораздо удобнее разбить это на две функции: одна отвечает за подсчёт, а другая за описание имени в этом конкретном формате.

```javascript
// Просто считает буквы
function countLetters(str) {
  let count = 0
  for (const letter in str) {
    count += 1
  }
  return count
}

// Просто красиво оформляет текст
function describeName(name) {
  const count = countLetters(name)
  return `The name has ${count} letters`
}
```

И тогда эту общую функцию подсчёта можно использовать и здесь, при сборке строки, и в любом другом месте, где она понадобится. Когда нам нужно посчитать буквы в строке, эта функция никак не связана с выводом текста.

Каждую из этих функций можно прочитать отдельно и сразу понять, что она делает.

Когда функции становятся сложнее и их становится больше, именно этот приём отличает аккуратный, читаемый код от полной путаницы и беспорядка.

Здесь стоит ещё раз упомянуть одну вещь: то, что вы создаёте внутри функции, недоступно другим функциям, если вы намеренно не вернёте это наружу.

Поэтому если вы попробуете обратиться к переменной `count` (количество) изнутри `describeName` (опиши имя), у вас ничего не получится: она принадлежит другой функции.

В JavaScript можно создавать переменные на самом верху, выше всего остального, и они будут общими для всех функций. Но я очень рекомендую так не делать, если для этого нет действительно веской причины.

Чем независимее каждая функция, тем чище будет ваш код и тем меньше багов у вас появится. Такие функции называют чистыми (англ. *pure*).
